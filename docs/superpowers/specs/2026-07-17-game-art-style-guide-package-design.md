# 游戏美术风格指导包设计

## 1. 文档状态

- 日期：2026-07-17
- 状态：已确认
- 范围：风格探索到图片生成等资产生产模块之间的游戏美术指导能力
- 目标产品：灵帧工坊（Sprite Forge Lab）

## 2. 背景

风格探索已经能够围绕“风格方向”组织参考图、生成结果、分组、画布和提示词，但这些内容尚未被整理成后续资产生产可以稳定、低成本引用的指导数据。

原有“确认项目风格”强调从多个方向中选出唯一项目风格，不适合实际游戏美术流程。一个项目可能同时维护像素风、水墨风、宣传插画风等多个可用方向，也可能在不同资产阶段切换指导方向。因此，每个风格方向都应能独立产出指导包，已发布的指导包均可被后续生产模块选用；项目只额外保存一个“默认指导包”，不再确认唯一项目风格。

指导包面向游戏美术生产，不应只是图片风格关键词集合。它需要同时覆盖贯穿项目的视觉基因，以及场景、角色、UI、技能特效、道具装备等专业设计模块。

## 3. 设计目标

1. 将任意风格方向整理为可编辑、可发布、可追溯的游戏美术指导包。
2. 让人可以通过风格板和参考图快速理解方向，让模型可以通过结构化规则和少量精选参考图稳定复用方向。
3. 默认按资产类型引用“全局视觉基因＋对应专业模块”，避免把整个指导包全部提交给模型。
4. 默认控制提示词长度、参考图数量、重复上传和额外分析调用，在成本和精度之间取得平衡。
5. 允许用户在单次生成中切换指导包、模块和引用策略，但不修改已发布指导包。
6. 保存每次生成实际使用的指导版本、规则、参考图和临时覆盖，保证历史可追溯。

## 4. 非目标

第一版不包含：

- 完整游戏 GDD 或世界观编辑器；
- 完全自由定义的任意指导模块类型；
- 指导包市场、跨项目继承和在线协作审批；
- 每次生成前重新调用远端 AI 总结整个指导包；
- 通过无限增加参考图承诺绝对一致的模型输出；
- 自动替代美术负责人对最终内容的判断。

## 5. 核心概念

### 5.1 风格方向

风格探索中的内容容器，继续持有参考图、生成结果、画布分组和描述等探索资料。

### 5.2 游戏美术指导包

从某个风格方向整理出的生产指导实体。一个方向至多存在一个活动草稿和任意多个不可变发布版本。

### 5.3 默认指导包

项目级默认选择。图片生成等资产生产模块打开时默认选中该指导包的最新发布版本。默认不表示唯一、确认或排他，其他已发布指导包仍可使用。

### 5.4 全局视觉基因

所有资产生产都会应用的核心规则，负责跨专业模块的一致性。

### 5.5 专业设计模块

按生产领域组织的指导切片。第一版使用固定模块类型，按项目需要启用。

### 5.6 编译后指导

系统针对某次生产任务，从已发布指导版本中选择必要模块、裁剪规则并挑选少量参考图后得到的实际模型输入。

## 6. 指导包内容结构

### 6.1 人类可读内容

- 风格名称与一句话摘要；
- 自动排版的可视化风格板；
- 全局及各模块的精选参考图；
- 设计原则、推荐做法、禁止项和版本说明。

风格板由已确认的真实内容、色板和关键词确定性排版生成，不调用图片生成模型重新创作。它用于确认、展示和导出，默认不作为模型参考图，避免拼贴内容对生成模型造成语义混淆。

### 6.2 全局视觉基因（必选）

1. 世界基调与目标情绪；
2. 贯穿主旨、母题、文化符号与重复元素；
3. 造型、比例、轮廓与形状语言；
4. 主辅色谱、颜色语义、材质体系和光照逻辑；
5. 表现技法、描边、渲染、纹理和细节尺度；
6. 跨模块统一的推荐做法和禁止项；
7. 全局风格提示片段、负面提示片段和参考图职责。

### 6.3 第一版专业模块

#### 场景与环境设计

- 建筑与文化体系；
- 地貌、水体、植被和天气；
- 空间层次、构图、视角和尺度；
- 场景叙事、氛围与可交互区域表现；
- 场景专用提示片段、负面约束和参考图。

#### 角色与生物设计

- 轮廓、体型、比例和年龄表达；
- 面部、发型、服装、装备与材质；
- 阵营、职业、身份和稀有度差异；
- 姿态、动作和性格气质；
- 角色专用提示片段、负面约束和参考图。

#### UI / HUD 设计

- 信息层级、布局密度和框架形状；
- 字体、字号、图标、控件和颜色语义；
- 交互状态、反馈、动效和可读性；
- 与世界观母题的连接方式；
- UI 专用提示片段、负面约束和参考图。

#### 技能与 VFX 设计

- 能量来源、形态和颜色语义；
- 起手、持续、命中、消散的运动节奏；
- 层次、打击反馈、范围和战斗可读性；
- 不同元素、职业和等级的差异；
- 技能特效专用提示片段、负面约束和参考图。

#### 道具与装备设计

- 类别轮廓、功能结构和使用方式；
- 材质组合、工艺、磨损与年代感；
- 品质、稀有度、阵营和职业差异；
- 道具装备专用提示片段、负面约束和参考图。

后续可以新增预定义模块类型，例如图标与物品、地图表现、宣传插画，但第一版不开放完全自由字段。

### 6.4 每个专业模块的统一字段

- 模块定位与适用资产类型；
- 与全局视觉基因的关系；
- 领域设计规则；
- 推荐做法与禁止项；
- 3–6 张候选参考图及职责标签；
- 风格提示片段和负面提示片段；
- 完整性状态、资料不足原因和人工备注。

## 7. 草稿、发布与默认机制

### 7.1 生成草稿

用户在风格方向中点击“生成指导包”。具备视觉分析能力时，系统分析当前方向的参考图、成功生成结果、提示词、分组和描述，产生草稿：

- 推断全局视觉基因；
- 识别可能需要启用的专业模块；
- 将内容分类到对应模块；
- 为参考图标注职责和优先级；
- 生成结构化规则、提示片段、禁止项和风格板布局。

AI 只生成草稿。用户可以启用或关闭模块、修改规则、增删和排序参考图。

### 7.2 发布版本

发布前执行完整性和素材可用性检查。发布后形成不可变版本，并预编译各模块的短规则胶囊、参考图职责、远端素材 ID 和文件指纹。方向内容后续变化不会自动修改已发布版本；重新归纳只更新活动草稿。

### 7.3 设为默认

只有已发布指导版本可以设为项目默认。项目同时只有一个默认指导包，但不存在唯一“确认项目风格”。删除默认包或使其不可用时，生产模块明确回退到“不使用风格”，不自动切换为其他包。

## 8. 生产模块引用流程

### 8.1 默认选择

图片生成、视频生成和后续资产生产模块打开时：

1. 默认选中项目默认指导包的最新发布版本；
2. 用户可切换其他已发布指导包；
3. 用户可选择“不使用风格”；
4. 用户可对本次任务临时调整模块、参考图、风格强度和提示片段。

临时调整只属于当前任务，不写回指导包。

### 8.2 资产类型路由

默认路由规则：

| 资产类型 | 默认指导组合 |
| --- | --- |
| 场景、环境、建筑 | 全局视觉基因＋场景与环境 |
| 角色、NPC、敌人、生物 | 全局视觉基因＋角色与生物 |
| UI、HUD、面板、控件 | 全局视觉基因＋UI / HUD |
| 技能、法术、战斗 VFX | 全局视觉基因＋技能与 VFX |
| 技能图标 | 全局视觉基因＋技能与 VFX＋精简 UI 规则 |
| 道具、装备、武器 | 全局视觉基因＋道具与装备 |
| 未识别类型 | 全局视觉基因；提示用户补选专业模块 |

用户可以在本次任务中增删模块。系统不得自动加载所有模块。

### 8.3 提交输入合并

实际模型输入由以下内容按顺序组成：

1. 用户的资产需求提示词；
2. 全局视觉基因的编译片段；
3. 主专业模块的编译片段；
4. 必要的辅助模块精简片段；
5. 本次临时覆盖；
6. 合并去重后的负面约束；
7. 参考图素材 ID 和模型支持的引用参数。

风格规则只控制视觉表达，不应静默改写用户要求的主体、数量、动作或功能语义。

## 9. 成本与精度策略

### 9.1 发布时预编译

发布指导版本时完成成本较高的工作：

- 压缩并去重全局和模块规则；
- 为参考图生成领域、职责、优先级和质量标签；
- 使用共享文件指纹缓存解析或上传远端素材 ID；
- 保存模型兼容信息和来源快照。

生成时不重新调用远端 AI 总结指导包，也不重复上传已缓存素材。

### 9.2 三档引用预算

| 档位 | 文本预算目标 | 模块范围 | 参考图预算 | 用途 |
| --- | ---: | --- | ---: | --- |
| 经济 | 不超过约 450 tokens | 核心＋1 个主模块 | 0–1 | 批量草稿、方向探索 |
| 智能平衡（默认） | 不超过约 900 tokens | 核心＋1 个主模块，必要时少量辅助规则 | 通常 2 | 常规正式生产 |
| 精准 | 不超过约 1600 tokens | 核心＋最多 2 个相关模块 | 3–4 | 关键角色、主场景、核心 UI 和特效 |

预算是上限而非必须用满。模型适配器可以根据实际能力和计价方式进一步降低上限，不得超过模型支持的参考图数量。

### 9.3 参考图选择

参考图不是简单按相似度取前几张，而是先满足职责覆盖，再控制重复：

1. 过滤不属于已选模块、素材不可用或当前模型不支持的图片；
2. 根据任务类型、提示词、职责标签、人工优先级和图片质量计算相关度；
3. 优先覆盖互补职责，例如角色轮廓＋服装材质，而不是选择两张几乎相同的角色图；
4. 对视觉高度重复的候选执行降权；
5. 应用档位和模型数量上限；
6. 向用户展示最终参考图及每张图被选择的原因。

第一版运行时使用发布版本中已生成的文本标签和确定性评分，不为每次任务调用远端视觉模型。未来可以选配本地嵌入检索，但不作为第一版依赖。

### 9.4 提高精度的措施

- 只组合全局核心和相关专业模块，避免跨领域规则污染；
- 每张参考图承担明确职责；
- 提交前检查任务提示与指导规则冲突；
- 根据模型能力选择参考输入格式、数量和顺序；
- 保存最终编译文本、参考图、模型参数和版本快照；
- 提供可选的模块试生成和精准模式一致性检查。

系统不能绝对保证随机生成模型每次输出符合预期，但必须保证提交输入与指导版本一致、预算可解释、降级可见、历史可复现。

## 10. 界面设计

### 10.1 风格探索

移除“确认项目风格”“当前项目风格”“已确认为项目风格”等唯一状态表达。

风格方向显示指导包状态：

- 未生成；
- 草稿；
- 已发布 vN；
- 项目默认。

方向操作根据状态提供“生成指导包”“编辑草稿”“查看发布版”“发布新版本”“设为默认”。这些状态不改变方向内已有参考图和生成结果的组织方式。

### 10.2 指导包编辑工作区

使用独立工作区，不把完整编辑器塞入现有窄详情栏。工作区包含：

- 顶部：方向、草稿来源、重新归纳、保存和发布；
- 左侧：风格板和精选参考图；
- 右侧：全局视觉基因和专业模块导航、结构化规则与提示片段；
- 发布检查：完整性、素材可用性、资料不足模块和冲突提示。

### 10.3 资产生产

生成面板增加紧凑的指导包选择区：

- 已选择包、版本和默认标记；
- 自动应用的模块；
- 引用策略：经济、智能平衡、精准；
- 实际参考图数量和职责摘要；
- “查看并调整本次引用”；
- “不使用风格”。

调整浮层允许本次切换模块、删改参考图、修改风格强度和文本覆盖，并明确提示不会修改指导包。

## 11. 数据与存储设计

### 11.1 项目清单

项目清单新增：

```json
{
  "default_style_guide_package_id": "guide_xxx"
}
```

旧字段 `style_status` 和 `current_style_direction_id` 不再驱动新界面。为兼容已有项目可以暂时保留读取，但不得继续维护“唯一确认风格”的业务规则；完成迁移后再单独移除。

### 11.2 指导包注册表

新增 `.sprite-lab/style-guide-packages.json`，仅保存包级索引：

```json
{
  "schema_version": 1,
  "packages": [
    {
      "id": "guide_xxx",
      "style_direction_id": "style_xxx",
      "draft_revision": 3,
      "latest_published_version_id": "guidever_xxx",
      "enabled_module_types": ["environment", "character", "ui_hud"],
      "updated_at": "..."
    }
  ]
}
```

### 11.3 草稿与发布版本

每个包使用独立目录：

```text
.sprite-lab/style-guides/<package-id>/draft.json
.sprite-lab/style-guides/<package-id>/versions/<version-id>.json
production/style-guides/<package-id>/<version-id>/style-board.png
```

发布版本包含：

- 包和方向 ID、版本号、发布时间；
- 来源内容 ID、文件指纹和提示词快照；
- 全局视觉基因；
- 已启用专业模块；
- 编译提示片段；
- 参考图 ID、职责、优先级、远端素材 ID 和可用状态；
- 风格板相对路径；
- 完整性检查结果和兼容信息。

发布版本不可原地修改。新发布产生新文件。

### 11.4 生成记录快照

生成记录新增：

- `style_guide_package_id`；
- `style_guide_version_id`；
- `style_guide_mode`；
- `style_guide_module_types`；
- `style_guide_reference_snapshot`；
- `style_guide_prompt_snapshot`；
- `style_guide_overrides`。

历史记录不得通过当前指导包反查后动态重建当时输入。

## 12. 服务边界与接口

### 12.1 指导包服务

独立的 `StyleGuideService` 负责：

- 草稿与发布版本读写；
- 来源快照和完整性检查；
- 风格板布局数据与导出；
- 默认包设置；
- 版本查询和删除约束。

它不负责具体模型调用。

### 12.2 分析适配器

`StyleGuideAnalyzer` 接收风格方向内容和启用模块，返回结构化草稿。它要求具备图像理解能力，但应通过能力接口接入，不能把某个供应商名称写入业务模型。

视觉分析能力缺失时：

- 自动归纳按钮显示能力缺失；
- 用户仍可从空模板或上一个发布版本复制草稿；
- 已发布指导包继续可用。

### 12.3 运行时编译器

`StyleGuideCompiler` 是确定性组件，输入为发布版本、资产类型、用户提示、模型能力、引用档位和本次覆盖；输出为编译提示、负面约束、参考素材列表、警告和预算摘要。

编译器不得执行远端 AI 调用。模型提交适配器只消费编译器输出。

### 12.4 建议 API

- `GET /api/v1/projects/{projectId}/style-guides`
- `GET /api/v1/projects/{projectId}/style-guides/{packageId}`
- `POST /api/v1/projects/{projectId}/styles/{directionId}/style-guide/draft`
- `PUT /api/v1/projects/{projectId}/style-guides/{packageId}/draft`
- `POST /api/v1/projects/{projectId}/style-guides/{packageId}/publish`
- `PUT /api/v1/projects/{projectId}/style-guides/{packageId}/default`
- `POST /api/v1/projects/{projectId}/style-guides/{packageId}/compile-preview`

自动归纳可以是异步任务；手动保存、发布和编译预览保持同步且具备明确错误返回。

## 13. 异常处理与降级

- 视觉分析能力缺失：允许人工创建，不阻塞方向和发布版使用。
- 模块资料不足：生成部分草稿并标记缺口；允许人工补齐后发布。
- 参考图远端素材 ID 失效：提交前只自动修复一次；智能平衡可经用户确认后排除失效图，精准模式阻止提交。
- 当前模型参考图上限较低：自动裁剪并展示实际数量，不声称使用未提交的素材。
- 模型不支持参考图：降级为文本规则并明确提示；精准模式由用户确认是否继续。
- 用户提示与指导规则冲突：列出冲突字段，允许本次保留任务要求、保留指导规则或关闭对应规则。
- 默认包没有可用发布版本：回退“不使用风格”并提示，不自动替换。
- 发布过程中部分文件写入失败：不得更新注册表的最新发布版本指针；清理未完成临时文件。

## 14. 精度校准与反馈

### 14.1 发布前检查

检查全局视觉基因必填项、启用模块完整性、参考图职责覆盖、素材可用性、提示片段长度、重复规则和明显矛盾。

### 14.2 模块试生成

每个模块提供可选低成本校准任务，例如：

- 角色：标准全身角色样张；
- 场景：标准中景环境概念图；
- UI：标准信息面板；
- 技能 VFX：标准单技能表现；
- 道具装备：标准单件装备展示。

试生成不是发布硬门槛，避免每次更新产生强制成本；在第一次设为默认前提供明显建议。

### 14.3 一致性检查

智能平衡模式记录用户“符合 / 偏离”反馈及偏离模块。精准模式可以选配额外视觉评估，按色彩、轮廓、材质、构图和模块规则给出偏离说明。额外调用必须在提交前展示成本，默认不开启。

## 15. 测试策略

### 15.1 单元测试

- 资产类型到模块的默认路由；
- 三档文本和参考图预算；
- 提示片段合并、去重、优先级和冲突检测；
- 参考图职责覆盖、相关度、冗余降权和上限裁剪；
- 草稿修改、不可变发布版本和版本号；
- 默认包设置和删除后的回退；
- 生成记录快照不依赖当前包状态。

### 15.2 服务与 API 测试

- 创建草稿、保存、发布、设为默认和读取版本；
- 发布失败的原子性和临时文件清理；
- 文件指纹与远端素材 ID 复用；
- 缺少视觉分析能力时的人工流程；
- 失效素材 ID 修复一次及两种模式的不同降级；
- 模型能力限制下的编译预览和最终提交一致性。

### 15.3 前端交互测试

- 方向中未生成、草稿、已发布和默认状态；
- 独立编辑工作区的模块启停、参考图调整和发布检查；
- 生产面板默认选包、切换包、不使用风格和本次覆盖；
- 经济、智能平衡和精准档的预算摘要；
- 冲突、资料不足、能力缺失和模型降级提示；
- 生成历史展示实际使用的版本、模块和参考图。

### 15.4 质量验收样本

为每个第一版专业模块准备至少 3 个固定任务，覆盖经济、智能平衡和精准档。验收重点不是要求随机结果完全一致，而是确认：

- 编译器只引用正确模块；
- 实际参考图数量符合预算和模型限制；
- 参考图职责互补且来源可追溯；
- 任务主体语义没有被风格规则改写；
- 同一发布版本和相同覆盖得到相同的编译输入；
- 偏离反馈能定位到全局或具体专业模块。

## 16. 迁移与交付顺序

建议按以下顺序实施：

1. 数据模型、版本存储、默认包和确定性编译器；
2. 手动创建和编辑指导包、发布检查和生产模块选择；
3. 参考图职责、预算档位、素材 ID 缓存与生成记录快照；
4. 视觉分析适配器和 AI 草稿归纳；
5. 风格板导出、模块试生成和可选一致性检查；
6. 移除旧“确认项目风格”界面与唯一状态规则。

第一阶段即使没有视觉分析模型，也能通过人工指导包完成端到端生产闭环。

## 17. 验收标准

1. 每个风格方向都能独立拥有草稿和多个发布版本。
2. 项目能设置一个默认指导包，但不存在唯一确认风格或自动归档其他方向。
3. 指导包包含必选全局视觉基因及可选游戏美术专业模块。
4. 资产生产默认加载全局核心和对应模块，用户可本次调整或关闭。
5. 智能平衡模式不会默认提交整个指导包，通常只使用 2 张职责互补参考图。
6. 风格板不作为默认模型参考输入，已缓存素材不重复上传。
7. 编译预览与最终提交使用相同规则，所有降级和冲突对用户可见。
8. 发布版本不可变，历史生成保存实际输入快照并可追溯。
9. 缺少视觉分析能力时仍可人工创建、发布和使用指导包。
10. 相关自动化测试和固定质量验收样本覆盖核心路由、预算、版本、降级和生产闭环。
