# 风格模板简略版 / 详细版设计

状态：已确认  
日期：2026-07-22

## 1. 背景与结论

当前“视觉指导图”生成链路同时承担人工评审和图片模型参考两种职责。实际任务 `0de6de9a-6e2b-4042-bcb7-eb57407c3aef` 使用 `GPT-Image2-Medium`，把角色模块图与视觉基因锚点图合并为一张参考拼图提交。结果较好地继承了深色背景、低饱和配色和设定板版式，却丢失了 Q 版头身比、极简五官、短肢圆形和低细节等核心造型语言。

问题不是参考图完全无效，而是复杂指导板同时携带了版式、色卡、多样例、局部展示和主体内容，模型无法稳定区分哪些信息属于风格。长篇提示词还把“完整面部与材质细节”“多个样例和局部放大”等要求与小游戏精简规格混在一起，进一步放大了冲突。

本次确认的解决方向不是新增第二套风格系统，而是扩展现有指导包、视觉运行、版本、仓库和编译器：同一个风格模板版本支持简略版与详细版两种规格。简略版主要给图片模型使用，详细版保留当前人工评审价值。

参考依据：

- [OpenAI Image generation](https://developers.openai.com/api/docs/guides/image-generation)：GPT Image 2 会高保真处理输入图片，但跨次视觉一致性仍不是强保证。
- [Google Imagen 风格自定义](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/image/style-customization?hl=zh-cn)：风格参考应在请求和提示中显式声明职责，不应依赖参考图自行承担构图控制。
- [Gemini 图片生成](https://ai.google.dev/gemini-api/docs/image-generation?hl=zh-cn)：对象、角色和风格参考具有不同职责，后续生成可继续引用已生成图片保持一致性。
- [OmniGen](https://github.com/VectorSpaceLab/OmniGen)：多模态提示需要明确指出输入图片中应被引用的对象或特征。

## 2. 目标

- 将现有“生成视觉指导图”对外统一为“生成风格模板”。
- 同一风格模板版本支持 `compact`（简略版）与 `detailed`（详细版）。
- 默认生成更适合图片模型消费的简略版，同时允许只生成详细版或两种都生成。
- 继续复用现有三步向导、视觉运行、持久化状态机、版本固化、仓库、确认使用和资产生成编译器。
- 不在正式生成前增加大模型分析参考图的步骤。
- 让参考图职责、计费、取消、失败重试和历史快照可追溯。
- 旧版本无需文件迁移即可继续使用。

## 3. 非目标

- 不训练 LoRA、IP-Adapter 或其他专用风格模型。
- 不保证不同供应商、不同模型版本之间像素级一致。
- 不自动替换已经确认使用的模板版本。
- 不把简略版做成新的平行模块、第二套仓库或第二套编译器。
- 第一版不默认为同一模块生成两张或更多简略版增强参考图。
- 不自动触发任何额外付费生成任务。

## 4. 术语与兼容边界

### 4.1 对外名称

- 入口：`生成风格模板`
- 仓库：`风格模板仓库`
- 版本：`风格模板 vN`
- 规格：`简略版`、`详细版`

### 4.2 内部名称

为了降低迁移风险，第一版允许继续保留 `style_guide_package`、`visual_run`、`visual_node` 等内部字段和服务名，只在数据中新增规格维度。不得为了重命名复制一套领域服务或 API。

### 4.3 规格定义

- `compact`：AI 生产参考。每个节点生成一个完整、纯净、连贯的视觉样例。
- `detailed`：现有完整指导规格。保留色卡、形状、比例、材质、多个样例和本地准确标签等信息。

旧版本没有规格字段时确定性读取为 `detailed`，不修改旧 JSON、图片文件或不可变历史快照。

## 5. 生成向导

继续复用当前三步向导：

1. 选择参考图；
2. 选择生成模式、模板规格、细节密度、模块、模型和参数；
3. 提交、查看进度、取消、重试和固化。

第二步新增“模板规格”复选区：

- `简略版｜AI 生产推荐`
- `详细版｜完整视觉指导`

交互规则：

- 默认勾选简略版，详细版默认不勾选。
- 至少保留一种规格；试图取消最后一个选项时保持原选中并给出简短提示。
- 可以只生成简略版、只生成详细版或两种同时生成。
- 活动运行期间规格、参考图、模式、细节密度、模块、模型和参数统一只读。
- 关闭向导不取消任务，重新打开后恢复同一运行和规格选择。
- 提交按钮显示实际远端任务数，例如“生成 6 张模板”。

## 6. 生成模式与任务图

### 6.1 整体生成

- 仅简略版：生成一个 `compact / overall` 远端节点。
- 仅详细版：沿用现有 `detailed / overall` 远端节点和本地整理。
- 两种规格：分别生成两个独立远端节点；不得用同一张图同时充当两种规格。

### 6.2 分模块生成

每种所选规格拥有自己的任务链：

```text
variant / anchor
  -> variant / scene
  -> variant / character
  -> variant / ui
  -> variant / vfx
  -> variant / prop
  -> detailed variant only: local template renderer
```

模块仍按用户选择启用；视觉基因锚点固定启用。简略版与详细版的同名模块是两个独立节点，分别保存提示词、参考图快照、模型参数、费用、生成记录和结果。

同一规格的专业模块依赖该规格锚点。重新生成某一规格的锚点，只失效并重建该规格的下游节点，不影响另一规格已经成功的结果。

## 7. 简略版视觉内容

简略版统一遵循“一个完整生产样例”，禁止色卡、文字、标签、形状样本、多格排版、转面或表情合集、局部放大和无关资产堆叠。

### 7.1 全局锚点

生成一张统一世界观的完整代表性画面。它应同时体现媒介、形状语言、色彩关系、明暗、材质和细节密度，但不能是信息图或指导板。

### 7.2 场景与环境

生成一个完整、可读的原创游戏场景，体现空间层次、光照、环境材质、色彩关系与生产密度；不生成场景缩略图合集。

### 7.3 角色与生物

生成一个原创完整角色或生物，使用单一自然姿态和简单背景，清楚体现头身比例、轮廓、五官抽象程度、边缘处理、上色和细节密度；不生成转面、表情或姿势合集。

### 7.4 UI / HUD

生成一个完整代表性界面组件或局部界面，不生成可读文字，不制作按钮、图标和窗口的组件合集板。

### 7.5 技能与 VFX

生成一个完整孤立特效，背景与效果具有足够对比，清楚体现核心形状、边缘、粒子、色彩和发光方式；不生成多种特效合集。

### 7.6 道具与装备

生成一个完整原创道具或装备，居中清楚展示造型、材质、边缘和细节密度；不生成多道具陈列板。

现有“精简 / 标准 / 丰富”细节密度继续作为生产规格进入两种规格的提示词、输入签名和历史快照。它控制视觉复杂度，不改变简略版“单一完整样例”的构图原则。

## 8. 详细版视觉内容

详细版沿用当前视觉指导逻辑：

- 可以展示色彩、形状、比例、材质、多个样例和必要的局部说明。
- 模型仍只生成无标题、无标签、无伪文字的视觉内容。
- 准确标题、模块名和色板标签继续由本地排版器生成。
- 当前整体模式、分模块模式、细节密度、依赖顺序和本地模板整理继续生效。

详细版主要供人工理解、评审和导出；当简略版缺失时，它也是旧流程的兼容回退。

## 9. 提示词架构

### 9.1 生成简略版

简略版提示词由确定性模板组成：

1. 原创任务与对应模块的单一样例构图；
2. 当前细节密度生产规格；
3. 输入参考图的风格继承职责；
4. 禁止继承参考图主体、身份、姿势、构图、文字和展示版式；
5. 简略版通用负面约束。

不增加“先分析参考图并生成风格说明”的模型调用。创建模板时使用用户已经填写的风格方向、原始参考图和固定系统提示；系统只做确定性拼接。

### 9.2 正式资产生成

正式提示词按四层编译：

1. **任务内容**：要生成什么；
2. **输出规格**：数量、视角、画幅、背景和完整性；
3. **风格引用协议**：只继承比例体系、形状语言、线条、色彩关系、明暗、材质表达和细节密度，不继承参考图主体、身份、姿势、构图和背景；
4. **参考图职责**：明确图片 1 是风格、图片 2 是身份、图片 3 是姿势等。

通用资产提示词模板必须保持风格中立，不得无条件附加“写实、高细节、电影感、大师级、复杂材质”等可能覆盖参考图的词。

简略版应用时采用固定强风格遵循，不显示或编译当前仅靠 `subtle / style guidance / strong style adherence` 切换的伪权重。详细版回退路径第一版继续保留现有强度兼容逻辑。

## 10. 风格参考选择与拼接

资产类型到风格参考的选择顺序固定为：

1. 当前资产类型对应模块的简略版；
2. 全局简略版；
3. 当前资产类型对应模块的详细版；
4. 全局详细版。

一次资产生成只选择一张风格模板参考图。用户额外添加的身份、姿势、构图或内容参考图继续保留，但每张图必须有明确职责。

参考图优化必须变为职责感知：

- 风格模板不得与身份、姿势、构图或普通内容参考图合并。
- 只有职责相同的普通内容参考图才允许本地拼接。
- 历史继续保存用户选择的原始参考图和职责；供应商实际输入另存优化快照。

## 11. 数据结构

### 11.1 运行

现有视觉运行增加：

```json
{
  "requested_variants": ["compact", "detailed"],
  "nodes": [
    {
      "id": "compact:character",
      "variant": "compact",
      "module_type": "character",
      "status": "succeeded"
    }
  ]
}
```

`requested_variants`、节点规格、提示词版本和细节密度都必须进入输入签名。不同规格选择不得复用旧运行。

### 11.2 发布版本

同一个不可变风格模板版本增加：

```json
{
  "variants": {
    "compact": {
      "anchor": {},
      "modules": {}
    },
    "detailed": {
      "anchor": {},
      "modules": {},
      "local_template": {}
    }
  }
}
```

每个规格分别保存模型、参数、参考快照、提示词快照、结果、费用和节点状态。旧版本缺少 `variants` 时由读取层映射为 `detailed`，不写回旧文件。

### 11.3 历史与追溯

视觉远端节点继续写入全局生成历史，并增加模板版本、规格、模块和运行节点标识。资产生产历史必须快照最终选择的模板版本、规格、模块、参考图片和编译提示词，后续模板变化不得改写历史任务。

## 12. 服务与 API 复用

- 扩展现有 `StyleGuideVisualService` 运行创建、推进、重试、取消和固化逻辑。
- 扩展现有 `StyleGuideService` 版本结构和兼容读取。
- 扩展现有 `compile_style_guide`，不新增第二个编译器。
- 继续使用现有视觉运行 REST 路由；请求和响应增加规格字段，不创建平行 API。
- 继续复用 `OmniGenService` 的素材缓存、任务历史、参考图上传、费用估算和结果下载。
- 前端继续复用现有视觉向导状态和渲染工具，不创建第二套弹窗或任务队列。

## 13. 费用

每种规格按真实远端任务单独报价：

```text
规格费用 = 每个远端节点的（有效参考图费用 + 生成费用）之和
总价 = 简略版费用 + 详细版费用
```

规则：

- 只选择一种规格时只显示该规格费用。
- 同时选择时分行显示简略版、详细版和合计。
- 同一批原始参考图被两个规格分别提交时，输入费用必须按两个任务链重复计算。
- 本地详细版模板排版不调用远端模型，不计入价格。
- 模型、分辨率、参考图有效数量、模块和规格变化后立即重新估价。
- 无法精确报价时显示原因，不得显示虚假零价。
- 规格默认值和预览不得创建远端任务或产生费用。

## 14. 状态、取消与重试

- 简略版和详细版节点分别记录 `submitting / queued / running / succeeded / failed / cancel_requested / canceled`。
- 父运行只要任一节点仍活动就保持生成中；只有不存在活动节点时才收敛终态。
- 支持取消全部，也支持只取消一种规格。
- 供应商不支持撤销已提交任务时，取消仅阻止该范围内尚未提交的后续节点；已提交任务可能继续完成并计费。
- 部分失败保留全部成功结果，并支持只重试失败节点。
- 共享 Token、余额、额度或预算错误仍应停止尚未提交的同批节点，避免制造必然失败的付费历史。
- 每个启用模块只要至少一种所选规格成功即可固化版本；失败规格在版本和仓库中明确显示，可后续补生成。
- 图片全部成功但固化失败时只重试固化，不重复调用图片模型。

## 15. 仓库与预览

- 仓库对外名称改为“风格模板仓库”。
- 继续按不可变版本分组；确认使用版本置顶，其他版本按完成时间倒序。
- 版本卡显示“简略版”“详细版”可用状态和缺失/失败状态。
- 模块同时存在两种规格时使用“简略版 / 详细版”页签；只存在一种时不显示空页签。
- 组内大图预览继续复用通用画廊，但顺序增加规格维度。
- 旧版本显示为“仅详细版”。
- “补生成简略版”基于旧版本可追溯输入创建一个新版本，不回写旧不可变版本；缺少可复用输入时要求用户重新选择参考图。

## 16. 资产生产行为

- 已确认版本存在匹配模块简略版时，自动选择该图片作为唯一风格模板参考。
- 匹配模块缺失时按第 10 节顺序回退，并在生成面板中显示实际使用的规格和模块。
- 简略版存在时不再把详细锚点和详细模块板同时提交。
- 风格模板参考和普通内容参考图分别显示职责与费用。
- 重新生成默认复用原任务快照中的版本、规格和职责，不静默切换到后来发布的模板。

## 17. 兼容策略

- 旧视觉运行、发布版本和生成历史保持原样。
- 读取层把无规格旧版本识别为 `detailed`。
- 旧确认版本仍可用于资产生产，并走详细版回退逻辑。
- 不批量移动、重命名或重新生成旧图片。
- 内部字段和路由优先兼容；产品文案逐步统一为“风格模板”。
- 新数据必须能被旧字段缺失的容错路径安全忽略，不允许启动时破坏项目。

## 19. 验收与验证

实施风险为 `L3（完整回归）`。计划至少覆盖以下 18 个聚焦场景：

1. 新向导默认只选简略版。
2. 最后一个规格不能被取消。
3. 只生成简略版的任务图、报价和固化正确。
4. 只生成详细版保持现有行为。
5. 同时生成两种规格时节点和费用分别计算。
6. 整体模式两种规格互不复用图片。
7. 分模块模式按规格维护独立依赖链。
8. 关闭并重开向导恢复规格和运行进度。
9. 只取消一种规格不影响另一规格。
10. 部分失败保留成功结果并只重试失败项。
11. 固化失败不重复提交付费图片任务。
12. 旧版本显示为仅详细版且无需迁移。
13. 补生成简略版创建新版本，不修改旧版本。
14. 编译器按“模块简略 → 全局简略 → 模块详细 → 全局详细”选择。
15. 风格模板不会与身份、姿势或构图参考合并。
16. 正式提示词包含明确参考职责且不混入指导板生成要求。
