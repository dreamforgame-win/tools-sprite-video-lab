# AI 创作工作台设计

日期：2026-07-13

## 目标

在灵帧工坊中新增独立一级模块“AI 创作”，使用 OmniGen MCP 提供图片生成，并打通“生成、历史、本地保存、加入图片处理、后续导出”的完整流程。页面和数据结构同时为视频生成预留扩展边界，但首版不实现视频生成。

## 已确认范围

- 顶部新增一级页签“AI 创作”，不隶属于图片处理。
- AI 创作采用“媒体创作台”布局：媒体导航、生成参数、结果画布、任务队列。
- 媒体导航首版显示“图片”“视频（待接入）”“历史”。视频入口禁用，不进入空页面。
- OmniGen MCP 图片模型列表、提交任务和查询任务通过本地后端代理。
- 所有任务自动进入持久化历史，包括提交中、等待、生成中、成功和失败状态；数据结构预留取消状态，但首版不提供取消动作。
- 成功结果下载到本地，用户可从结果画布或历史选择加入图片处理。
- 历史支持删除记录，或删除记录并删除 AI 创作目录中的本地文件。
- 移除现有登录/退出流程，改为默认游客的本地资料入口。
- 本地资料弹窗支持修改头像、名称和 OmniGen MCP Token。

## 信息架构

顶部一级导航顺序沿用现有工作台结构并加入“AI 创作”。具体相邻位置以实现时顶部宽度为准，优先保证所有一级入口在桌面宽度下稳定显示。

AI 创作内部结构：

1. 媒体导航：图片、视频（待接入）、历史。
2. 生成参数：提示词、模型、宽高比、分辨率及模型支持的可选参数。
3. 结果画布：当前任务结果、预览和主要流转动作。
4. 任务队列：等待、生成中、完成和失败任务的紧凑列表。
5. 历史视图：筛选、搜索、多选、批量加入处理和删除。

页面是固定工作台。媒体导航、参数区和队列保持稳定，各自需要滚动时使用明确的内部滚动区；结果画布负责主要预览，不被辅助控件遮挡。

## 本地资料

应用不再提供在线登录语义。首次启动使用以下默认资料：

- 名称：游客
- 头像：由名称首字生成的本地占位头像
- MCP 状态：未配置

点击顶部资料区打开编辑弹窗。弹窗包含头像选择、名称、MCP Token、测试连接、清除 Token 和保存动作。

头像选择本地图片后，由后端处理并保存到 `work/profile/`。名称和头像路径写入 `work/settings.json`。

Token 通过本地 API 提交给后端并写入 `work/settings.json`。前端不得使用 `localStorage` 保存 Token，也不得通过读取设置接口取得完整 Token。设置接口只返回 `configured`、验证状态和掩码摘要。已有 Token 时，输入框留空表示不修改；清除 Token 使用独立动作并二次确认。

测试连接调用 OmniGen MCP 的模型列表工具。成功时返回可用状态和图片模型数量；失败时返回经过脱敏的错误类型。任何日志、历史记录或 API 错误都不得包含 Token。

## OmniGen MCP 接入

本地后端连接：

- Endpoint：`https://omnigen.dianchu.cc/api/v1/mcp`
- 协议版本：`2024-11-05`
- 认证：`Authorization: Bearer <local token>`
- 响应兼容 `structuredContent` 与 `content[0].text` 两种载荷。

建议的本地 API：

- `GET /api/local-profile`：读取名称、头像 URL 和 MCP 配置状态。
- `POST /api/local-profile`：保存名称及头像。
- `POST /api/omnigen/token`：设置或替换 Token，不回传 Token。
- `DELETE /api/omnigen/token`：清除 Token。
- `POST /api/omnigen/test`：测试连接并返回可用模型摘要。
- `GET /api/omnigen/models`：取得图片模型与参数能力。
- `POST /api/omnigen/generate`：提交图片任务并创建历史记录。
- `GET /api/omnigen/tasks/<id>`：刷新单个任务状态。
- `GET /api/omnigen/history`：读取并筛选本地历史。
- `POST /api/omnigen/history/refresh`：批量刷新未完成任务。
- `POST /api/omnigen/history/delete`：按删除模式移除历史记录。

后端使用固定的 MCP 调用封装完成初始化、工具调用、载荷解析、超时和错误脱敏。浏览器不直接访问远程 MCP。

## 生成与持久化流程

1. 用户填写参数并提交。
2. 后端验证 Token、模型和参数。
3. 后端先创建本地历史记录，状态为 `submitting`。
4. MCP 返回远程任务 ID 后，记录转为 `queued` 或 `running`。
5. 前端轮询本地任务接口；刷新页面后，历史视图恢复未完成任务并继续轮询。
6. 远程任务成功后，后端验证结果 URL，只允许 HTTP/HTTPS，并下载到 `work/omnigen/results/`。
7. 后端验证图片格式和尺寸，生成本地预览信息，将记录更新为 `succeeded`。
8. 下载失败时保留远程结果地址和 `download_failed` 状态，允许重试下载。

生成历史保存在 `work/omnigen/history.json`。写入使用临时文件加原子替换，避免进程中断造成 JSON 损坏。首版使用 JSON，后续数据量增长时可以在不改变前端接口的情况下迁移到 SQLite。

历史记录至少包含：

- 本地记录 ID、媒体类型、创建和更新时间
- MCP 任务 ID、状态、进度和脱敏错误
- 提示词、模型 ID、模型显示名和生成参数
- 远程结果地址、本地文件相对路径、缩略图信息
- 文件类型、宽度、高度和字节数

## 历史与处理流转

所有任务提交后自动进入历史。历史支持按媒体类型、状态和时间筛选，并支持提示词或模型关键词搜索。

成功图片可以单选或多选“加入图片处理”。该动作把本地生成文件追加到现有 `imageImportFiles` 和图片导入画廊，然后切换到图片处理的“导入图片”步骤。已有图片不被清空，历史原件不被修改。

视频历史沿用同一数据结构。视频生成和“加入视频处理”在首版不启用。

结果卡和历史卡提供：

- 大图预览
- 加入图片处理
- 打开文件位置
- 删除

删除弹窗提供两种明确动作：

- 仅删除记录：从历史 JSON 移除，不删除文件。
- 删除记录及本地文件：二次确认后删除 `work/omnigen/results/` 下对应文件，再移除记录。

删除不得影响已导出到资源管理、绑定文件夹或外部目录的副本。后端只能删除解析后位于 AI 结果目录内部的文件。

## 状态与错误

- 未配置 Token：生成按钮禁用，提供打开本地资料弹窗的配置入口。
- Token 无效：显示验证失败状态，不清除用户输入，允许替换或重新测试。
- 余额不足、模型不可用、参数错误：保留失败历史并显示明确原因。
- 网络超时：任务保持可恢复状态，允许重新查询，不自动重复提交生成任务。
- 远程成功、本地下载失败：保留远程结果并提供重试下载。
- 历史文件损坏：保留损坏文件备份并使用空历史启动，同时显示本地恢复提示。
- 结果文件被外部删除：历史标记“本地文件缺失”，允许重新下载（远程地址仍有效时）或仅删除记录。

失败记录支持使用原参数重新生成。重新生成创建新记录，不覆盖原失败记录。

## 首版模型与参数

模型列表动态来自 MCP，不在前端硬编码。默认选择当前可用、价格较低且支持 1K 输出的图片模型；如果默认模型不可用，则选择列表中的第一个可用图片模型。

宽高比、分辨率和其他参数只展示所选模型声明支持的选项。价格信息作为紧凑辅助信息显示，不承诺本地计费准确性。

首版支持单任务文本生图。参考图上传、批量参数生成、视频生成和项目级外部 API 鉴权不在本次范围。

## 验证与验收

- 未配置 Token 时，AI 创作页可访问但不能提交生成，并可打开资料弹窗。
- 设置 Token 后前端任何响应和浏览器存储都不包含完整 Token。
- 测试连接能返回 MCP 可用状态和图片模型数量。
- 真实图片生成可从提交进入历史，刷新页面后继续追踪，成功后完成本地落盘。
- 成功图片可单选和多选追加到图片处理，且不覆盖已有导入图片。
- 失败任务保留错误与原参数，可重新生成。
- 两种删除模式行为正确，目录越界路径不能被删除。
- 本地文件缺失和下载失败都有可恢复状态。
- 桌面宽屏和窄屏下，一级导航、参数区、结果画布和任务队列不重叠、不撑破。
- 前端通过 `node --check app\\app.js`。
- 后端通过 `.venv-ai\\Scripts\\python.exe -m py_compile server.py`。
- `git diff --check` 无空白错误。
