# 视觉指导图仓库与确认版本设计

## 目标

把风格探索生成的视觉指导内容直接固化为可复用版本，避免人工编辑与发布成为核心闭环。每个风格方向拥有独立仓库，资产生产只引用明确确认的版本，并按“视觉基因 + 当前资产模块”控制成本和精度。

## 已确认体验

- 原“编辑指导包”入口改为“生成视觉指导图”，直接进入现有三步向导。
- 风格方向主内容拆为“方向资源”和“指导图仓库”两个页签。
- 指导图成功完成后自动创建不可变版本；新版本默认未确认，不替换当前使用版本。
- 每个指导包最多一个确认使用版本。确认版本固定置顶，其他版本按生成完成时间倒序。
- 默认展开确认版本和最新版本，其余版本折叠。
- 版本保留综合指导图、视觉基因锚点图及场景、角色、UI、技能 VFX、道具装备模块图。
- 第一版不删除版本，不建立重复仓库数据。

## 数据结构

复用现有指导包注册表和版本 JSON。包摘要新增：

- `confirmed_version_id`：当前确认使用版本 ID，缺省为空。
- `confirmed_version`：便于界面展示的版本号缓存。

视觉版本保存生成模式、模型、运行 ID、完成时间、模板路径、模块列表和稳定素材引用。旧项目迁移只补空确认字段，不自动把最新版本设为确认版本。

## 生成与固化

视觉运行的所有图片节点和本地模板成功后自动执行固化：

1. 将锚点、综合图和模块图以明确职责写入指导草稿。
2. 仅在文本字段为空时，用该次确定性生成提示补齐最小可编译内容，不覆盖历史人工内容。
3. 创建不可变版本，并在运行记录写入版本 ID 和版本号。
4. 若固化失败，运行进入 `finalize_failed`，保留全部图片结果；用户可只重试固化。
5. 通过运行 ID 检测已创建版本，使重试具备幂等性。

## 仓库与确认

仓库直接列出现有版本文件，不复制图片。后端返回版本资源可用性和确认状态。确认接口只更新包的确认指针，历史版本不变；确认前检查版本关键资源是否仍可用。外部删除文件后，仓库显示资源缺失，该版本不可确认或用于生产。

## 资产生产引用

- 可选指导包必须具有 `confirmed_version_id`。
- 预览和提交使用确认版本 ID，不再使用 `latest_published_version_id` 回退。
- 编译器保持现有路由：全局视觉基因加当前资产类型对应模块；智能平衡默认最多两张职责互补的参考图。
- 无确认版本时不允许作为生产指导包使用；项目默认包若未确认，生产回退为“不使用风格”并给出明确提示。
- 历史任务重新生成继续使用已保存的精确版本和引用快照。

## 错误处理

- 图片或模板节点失败：仅重试失败节点，不创建版本。
- 固化失败：保留结果并重试固化，不重新调用图片模型。
- 确认失败：保持原确认指针不变。
- 关键文件缺失：版本标记缺失并阻断确认与新生产；历史快照仍保留。
