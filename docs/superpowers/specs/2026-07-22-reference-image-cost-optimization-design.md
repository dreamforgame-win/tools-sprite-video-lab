# 参考图成本优化与生成面板统一设计

## 1. 目标

在风格探索图片生成和资产图片生成中复用同一套参考图优化、价格预估和生成操作规格：

- 两张及以上参考图默认在本地合并为一张实际输入图，减少 OmniGen 按输入参考图数量收取的费用；
- 在生成按钮下方展示基于当前模型、分辨率、参考图和生成数量的预计费用；
- 保留原始参考图和实际提交快照，使历史、重试和费用说明可追溯；
- 删除已有右上关闭按钮场景中的底部取消按钮；
- 优先扩展现有生成服务和共享界面能力，不建立相似的平行实现。

## 2. 设计原则

- 原始选择与实际输入分离：界面和历史保留用户选择的原图，供应商只接收优化后的有效输入。
- 默认省费但允许控制：两张及以上参考图默认合并，用户可以针对本次生成关闭优化。
- 单一规则来源：拼图、计费解释和历史快照由共享生成领域层负责，两套界面只消费结果。
- 价格诚实：只展示当前计费规则能够支持的确定性预估；动态 Token 等无法准确计算的部分明确标记，不以零价代替。
- 可追溯重试：重试沿用原任务的参考图优化开关、原始输入快照、模型参数和计费规则快照。
- 不裁切主体：本地拼图使用等比例完整容纳，不使用覆盖裁切。

## 3. 共享生成面板规格

风格探索和资产生产继续保留各自的业务差异，但以下内容统一结构与行为：

1. 参考图摘要、数量上限和管理入口；
2. “合并参考图以节省费用”控制及说明；
3. 提示词区域；
4. 模型、比例、分辨率和背景参数区；
5. 高级设置；
6. 生成主按钮；
7. 生成按钮下方的价格摘要。

共享区域使用现有密集工具台样式、字段尺寸、字号、间距、禁用状态和错误提示规则。实现应优先扩展当前 generation helper、参考图选择器和表单可用性函数，不复制一套 `style` 与一套 `asset` 计算逻辑。

允许保留的业务差异：

- 风格探索固定每次生成一张，结果归入当前风格方向；
- 资产生产支持 1、2、4、8 张批量生成，并可以应用风格指导包；
- 两者可以保留各自适用的背景选项和提示词默认值。

风格生成浮层已经提供右上关闭按钮，因此删除底部“取消”按钮。资产生成浮层同样只保留右上关闭按钮，不新增底部取消按钮。

## 4. 参考图优化交互

参考图区域在已有缩略图和操作区下增加共享控制：

- 名称：`合并参考图以节省费用`；
- 默认开启；
- 选择零张或一张时保持可见但不执行拼图，并显示“当前无需合并”；
- 选择两张及以上时显示“将 N 张参考图合并为 1 张实际输入”；
- 关闭时显示“将按 N 张参考图分别提交”；
- 模型不支持参考图时不显示可操作开关；
- 参考图数量、模型或风格指导包引用变化后立即刷新说明和价格。

优化开关只影响本次实际提交，不改变参考图库、风格方向参考图、已勾选状态或风格指导包内容。

资产生成应用风格指导包时，用户选择的参考图与编译后实际引用的指导包参考图合并去重，再统一进入优化流程。价格预估使用编译预览返回的实际引用数量；预览仍在更新或失败时，价格区域显示等待或不可预估状态，生成按钮继续遵守现有阻断规则。

## 5. 本地拼图规则

拼图由后端共享生成服务在调用 OmniGen 前完成，不由两个前端面板分别生成。

### 5.1 输入处理

- 对原始参考图按最终提交顺序去重；
- 两张及以上且优化开启时生成一张联系表式参考图；
- 一张参考图或优化关闭时保持原提交方式；
- 项目内本地文件、已有生成结果和带本地相对路径的指导包素材均可参与拼图；
- 无法安全解析到本地文件的公开 URL 或纯远端素材不能静默下载，保留为独立输入并在优化说明中体现实际输入数；
- 损坏、缺失或不支持的图片在提交前返回具体错误，不创建远端生成任务。

### 5.2 排版

- 根据图片数量选择接近方形的稳定行列数；
- 每个格子等尺寸，图片使用 `ImageOps.contain` 等比例完整容纳；
- 不放大低分辨率图片到明显失真，不裁切主体；
- 使用中性纯色背景和固定内边距，不添加序号、文字、水印或装饰；
- 统一转换到适合供应商输入的 RGB PNG；
- 对超大图片设置单图和总画布尺寸上限，避免无界内存占用。

### 5.3 缓存与文件生命周期

- 以有序原图内容指纹、拼图规则版本和关键排版参数生成稳定缓存键；
- 相同组合复用现有拼图文件；
- 拼图文件存放在项目生成工作区的受控缓存目录，不写入用户原图目录；
- 继续复用 `OmniGenService` 已有的文件指纹与远端素材 ID 缓存，相同拼图不重复上传；
- 删除生成历史时不直接删除仍可能被其他记录复用的拼图缓存；缓存清理由独立、可恢复的维护策略处理，不纳入本次界面操作。

## 6. 计费规则与预估

### 6.1 数据来源

`list_generation_models` 返回的 `billing_rules` 是计费规则来源。现有模型规范化层需要在保留 `pricing` 的同时透传并规范化 `billing_rules`，不得在两个前端面板中硬编码模型名称和价格。

计费解释由一个共享估算器完成，输入至少包含：

- 模型与计费规则；
- 分辨率或像素档位；
- 原始参考图数量；
- 优化后的预计实际输入数量；
- 单任务输出数量；
- 本次任务数量。

输出统一为结构化报价：参考图计费说明、单次生成价格、任务倍数、预计总价、币种、是否精确、不可计算原因和预计节省金额。

### 6.2 展示格式

风格探索固定一张：

`参考图 ¥0.10 × 1 + 生成 ¥0.395 = 预计 ¥0.495`

资产批量生成：

`（参考图 ¥0.10 × 1 + 生成 ¥0.395）× 4 张 = 预计 ¥1.98`

开启优化且确实减少实际输入时，追加次要说明：

`原 8 张已优化为 1 张实际输入，预计节省 ¥2.80`

预计节省按整批任务计算，即比较当前优化设置与关闭优化后的预计总价。

首张免费、阶梯价或固定输出价等规则按真实语义显示，例如：

`参考图首张免费，后续 ¥0.02 × 0 + 生成 ¥0.30 = 预计 ¥0.30`

对于依赖实际输入/输出 Token、供应商未提供可用回退价或当前参数不足以确定的模型：

- 展示已经能够确定的项目；
- 总价显示“暂无法精确预估”；
- 提供简短原因；
- 不将缺失项目按 ¥0 计算，也不阻止用户生成。

### 6.3 更新时机

以下变化必须刷新报价：

- 模型；
- 分辨率或影响像素档位的参数；
- 参考图选择和本地文件；
- 优化开关；
- 资产生成数量；
- 风格指导包、引用策略或实际参考图选择；
- 模型列表或计费规则重新加载。

共享估算函数负责格式化和金额舍入，两个面板不得各自实现一套金额算法。

## 7. 提交、历史与重试

生成记录继续保存用户原始 `params.reference_images`，并新增或等价保存：

- `reference_optimization.enabled`：本次是否开启优化；
- `reference_optimization.rule_version`：拼图规则版本；
- `reference_optimization.original_count`：去重后的原始参考图数；
- `reference_optimization.effective_count`：实际发送给供应商的输入数；
- `reference_optimization.composite_relative_path`：拼图相对路径，没有拼图时为空；
- `reference_optimization.unmerged_references`：无法参与本地拼图而保持独立的输入摘要；
- `cost_estimate`：提交时使用的计费规则、结构化公式、币种、单任务价、任务数、总价、是否精确和节省金额快照。

实际发送给 OmniGen 的 `inputs` 由优化结果生成，但不得用拼图路径覆盖历史中的原始参考图列表。

重试已有记录时：

- 使用记录中的原始参考图和优化开关；
- 使用原模型参数和生成数量口径；
- 重新验证本地文件和缓存；
- 报价快照保留原提交信息，同时可记录本次按最新规则计算的新报价，不能把旧历史伪装成新价格。

## 8. 服务边界

优先扩展现有 `OmniGenService`，由其承担：

- 模型计费规则规范化；
- 参考图路径验证和去重；
- 拼图生成与缓存；
- 实际输入准备；
- 结构化价格估算；
- 提交记录快照。

`server.py` 只负责校验项目上下文、合并风格指导包编译结果、调用共享服务并返回结构化结果。前端复用现有 `/api/v1/generation/tasks` 提交流程；如需要实时报价接口，应只暴露 `OmniGenService` 的同一估算器，不复制公式。

前端共享职责：

- 汇总当前可见参考图数量和指导包预览引用数；
- 维护本次优化开关；
- 请求或调用唯一的结构化报价入口；
- 用统一组件渲染价格摘要；
- 在两个面板的现有可用性同步函数中触发更新。

## 9. 错误与降级

- 计费规则缺失：显示“当前模型未提供价格规则”，允许生成。
- 计费规则格式无法识别：记录安全诊断信息，界面显示无法预估，不猜测价格。
- 拼图源文件缺失或损坏：阻止提交并指出具体参考图。
- 拼图生成失败：不自动退化为多张付费提交，避免在用户不知情时增加费用；提示用户重试或关闭优化。
- 只有部分输入可本地拼图：提交一张拼图加无法合并的独立输入，并按实际预计输入数报价。
- 实际输入超过模型上限：在远端提交前阻止，并显示优化后的实际数量。
- 报价请求失败：不清空已有选择；价格区域显示失败状态，生成是否可继续由参考图和模型能力校验决定。
- 页面关闭或切换页签：不改变已提交任务；重新打开时从现有任务历史恢复。

## 10. 项目规范补充

`docs/GENERATION_RULES.zh-CN.md` 增加共享能力优先规则：

> 相同或高度相似的业务能力，必须优先扩展已有组件、领域服务、数据结构和交互规范。没有明确业务差异时，不得新建平行入口、重复状态或第二套计算逻辑；确需分离时，应先记录差异、复用边界和迁移策略。

同时明确图片生成面板的参考图优化、模型参数、价格摘要和操作区属于共享规格。后续修改应先维护共享规则，再同步到所有使用方。

## 11. 验收标准

1. 风格探索和资产生产均显示同一规格的参考图优化控制和价格摘要。
2. 两张及以上本地参考图默认合并为一张实际输入，一张或零张时不生成拼图。
3. 用户可以关闭优化并看到价格和实际输入数量同步变化。
4. 拼图完整容纳所有图片，不裁切主体，不添加文字或编号。
5. 相同有序参考图组合复用本地拼图和已有远端素材 ID。
6. 原始参考图列表在历史中保持不变，记录同时包含实际输入和价格快照。
7. 风格指导包引用和用户参考图进入同一去重、优化与计费流程。
8. GPT Image 类按每张输入图和分辨率正确估价。
9. 首张免费和阶梯规则按真实语义估价。
10. 资产批量生成的参考图费与生成费均按任务数量计算。
11. 无法精确计算的 Token 计费模型不显示虚假总价。
12. 模型、分辨率、参考图、优化开关、数量和指导包变化都会刷新报价。
13. 风格生成面板删除底部取消按钮，右上关闭按钮可正常关闭。
14. 两个面板共用计费估算和展示逻辑，没有模型名称硬编码或双套金额公式。
15. 拼图失败不会静默回退为更昂贵的多图提交。
16. 重试使用原始参考图和原优化设置，并保留可追溯的报价信息。

## 12. 验证等级与范围

本功能涉及后端文件处理、供应商输入、模型计费规则、生成历史、重试以及两个前端入口，验证等级为 `L3（完整相关回归）`。

实施至少验证以下 16 类场景：

1. 零张参考图；
2. 单张参考图；
3. 两张参考图默认优化；
4. 多张参考图稳定排版；
5. 关闭优化后保持多输入；
6. 拼图缓存与远端素材 ID 复用；
7. 缺失、损坏和超大图片；
8. GPT Image 按参考图和 1K/2K/4K 计价；
9. 首张免费与阶梯计价；
10. 动态 Token 计费不可精确预估；
11. 资产 1/2/4/8 张整批价格；
12. 风格指导包追加、去重和优化；
13. 风格与资产面板状态和样式一致；
14. 生成、失败保护、历史快照与重试；
15. 右上关闭及底部取消按钮移除；
16. 现有图片生成、历史轮询和参考图上限回归。

自动验证包括相关 Python 单元测试、Node 前端测试、`node --check app/app.js`、`.venv-ai/Scripts/python.exe -m py_compile server.py omnigen_service.py`，以及活跃页面 `http://127.0.0.1:8895/app/index.html` 的关键路径浏览器冒烟。
