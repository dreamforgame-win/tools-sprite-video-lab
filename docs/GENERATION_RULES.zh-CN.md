# Sprite Video Lab 生成规范

这份文档是本项目后续 UI、交互和本地资源管理能力的生成基准。任何新功能、页面、控件或布局调整，先按这里实现；如果实际使用中发现规则不合适，优先修改本规范，再改代码。

## 工作方式

- 生成前先阅读本规范，确认要改的是哪一类界面或能力。
- 先沿用现有结构、类名、交互模型和视觉语言，不另起一套设计系统。
- 用户通过截图指出问题时，要判断问题属于“单次 bug”还是“规范缺口”。如果是规范缺口，先补充本文件。
- 每次交付需要说明改了哪些文件，以及是否需要刷新页面或重启后端。
- 前端改动至少验证 `node --check app\app.js`；后端改动至少验证 `.venv-ai\Scripts\python.exe -m py_compile server.py`。

## 界面风格

- 这是生产工具，不是落地页。首屏应直接呈现可操作界面，不做宣传式 hero。
- 布局优先紧凑、可扫视、可重复操作。避免大面积空白、重复大卡片、卡片套卡片。
- 对操作型工具，优先使用熟悉的控件：页签、分段按钮、图标按钮、色板、开关、输入框、列表、网格。
- 能用图形表达的控件不要写成长文字按钮；不常见图形必须有 `title` 和 `aria-label`。
- 信息摘要默认做成一行状态条或 chip。只有需要对比多项大指标时才使用大 summary card。
- 页面级区域可以是全宽面板；重复资源、项目、结果项可以用卡片。
- 固定格式元素要有稳定尺寸，动态文字要省略或换行，不允许撑乱布局。
- 滚动范围要明确。管理台类页面优先让内容列表滚动，顶部操作区和上下文信息保持稳定。
- 普通处理页允许页面滚动；只有明确要求固定工作台的模块才锁定页面滚动，并把滚动放到模块内部。
- 桌面端的 `视频转序列帧`、`视频处理`、`图片处理` 三个主工作台页签采用固定工作台滚动：顶部标题栏和左侧导航/信息区不随内容滚动，只有右侧内容模块滚动。
- 固定工作台内的步骤切换、跳过抠图、自动进入下一步等导航只能滚动模块内部内容区，不能调用整页滚动把内容重新顶到固定标题栏下方。
- 固定工作台里的左侧导航/信息区只能按内容自然高度排列，不允许为了填满工作台高度而拉伸导航项；内容超出时左侧区域自己滚动。

## 资源管理页规则

- 资源管理采用两级页面：第一层为项目总览页，负责创建、删除、修改项目；第二层为项目资源详情页，点击项目卡片进入。
- 项目总览页只展示项目卡片和项目级操作，不同时展示资源列表，避免项目列表和资源内容互相挤占空间。
- 项目总览卡片的最右侧主动作必须是进入项目，使用黑底主按钮；改名和删除收进“修改/项目设置”弹窗，删除不得直接暴露在卡片操作行。
- 项目资源详情页采用左右布局：左侧放返回、项目信息、项目操作、绑定文件夹状态和子文件夹页签；右侧只显示资源内容。
- 详情页侧栏中的按钮、输入框、页签和信息块不能贴住面板边缘，必须用内边距和间距隔开。
- 详情页不显示“收集抠图结果/收集拆图清单”这类临时收集按钮；文件夹未绑定时只显示“绑定文件夹”，绑定后显示已绑定文件夹列表、左侧短按钮“添加”和右侧长按钮“刷新文件夹资源”。
- 绑定文件夹支持多个路径。状态不再单独显示“已绑定/未绑定”提示块，状态通过绑定数量、路径列表和按钮文案表达。
- 项目内资源分两类：
  - 项目收集资源：抠图结果、拆图清单、后续导出物等。
  - 绑定文件夹资源：来自本地绑定文件夹的扫描结果。
- 图片结果等导出模块需要支持“导出到资源管理”：点击后使用项目选择弹窗选择目标项目，资源写入所选项目，不自动切换当前资源管理页面或当前项目。
- 拆图命名页调整输出尺寸后，“导出到资源管理”必须以当前导出清单的输出尺寸、缩放模式和裁剪/整图区域为准；同一资源再次导出到同一项目时要更新已有条目，不能因去重保留旧尺寸或旧预览。
- 项目收集资源移动到绑定文件夹时，必须把资源元数据中的裁剪区域和输出尺寸渲染成实际落盘文件；移动完成后文件夹扫描显示的尺寸应与导出尺寸一致，不能退回原始素材尺寸。
- 绑定文件夹是引用和展示，不默认复制文件。是否复制入库要作为后续明确功能设计。
- 资源预览区支持框选资源；框选只在资源网格区域内生效，不能影响缩略图预览按钮、文件夹折叠按钮和弹窗交互。框选采用切换语义：框到未选中资源时选中，框到已选中资源时取消，框外资源保持原状态。
- 文件夹资源必须保留层级。展示时按一级子文件夹归类：
  - 页签第一项为 `全部`。
  - 后续页签为 `项目资源`、`根目录`、各一级子文件夹。
  - `全部` 页签按文件夹分段显示。
  - 每个分段第一行只显示文件夹标题、箭头和数量。
  - 分段可展开/折叠；折叠时只保留标题，不显示预览图。
  - 展开时第二行开始显示预览图网格，然后接下一个文件夹分段。
  - 空文件夹也必须显示分段；展开时预留一行高度，并在中间显示“文件夹为空”。
- 资源列表区域自己滚动，项目标题、操作按钮、绑定文件夹状态和页签不随资源滚走。
- 资源管理页禁止整页滚动，且仅在资源管理页激活时锁定页面；项目总览只让项目卡片网格滚动，详情页只让左侧文件夹页签和右侧资源列表滚动。
- 资源列表区不重复显示大标题或说明文案；当项目标题和状态栏已提供上下文时，资源区顶部只保留页签和必要工具。
- 资源卡片保留稳定尺寸，文本区位置固定；预览图只在上方预览框内按资源原始比例缩放，以短边适配框内显示，不允许裁剪主体或撑开卡片。
- 带 `crop` 信息的项目资源必须按裁剪区域生成缩略图和大图预览，不能直接展示原始整图导致多个拆图资源看起来相同。
- 资源卡片至少显示来源类型、文件名、尺寸或路径摘要。

## 图片预览和透明底板

- 九宫格处理界面的处理面板、结果预览面板、画布背景和图片背景必须同步响应大图预览的透明/纯色底板设置；透明模式显示棋盘格，纯色模式使用当前底板颜色。
- 九宫格透明/纯色底板只作用于图片检查区域和预览框内部，预览框以外的面板背板、边框和工具区保持默认工作台样式。
- 九宫格线参数输入表示线条到对应边缘的距离：左/上为距左上边缘，右/下为距右下边缘；线贴边时参数为 0，拖拽和输入必须保持同一语义。
- 九宫格结果预览按实际像素尺寸显示：结果图尺寸小于预览区可用宽高时用 1:1 显示，超出时才按比例自适应缩小。
- 大图预览必须支持透明底板和不透明底板。
- 不透明底板默认白色，并可通过色板改色。
- 底板工具条使用胶囊形图标控件：
  - 棋盘格图标表示透明底板。
  - 实心方块表示不透明底板。
  - 色板圆点直接填充当前底板颜色。
- 色板只在不透明模式下显示。切到透明模式时收回，切回不透明时弹出，需要有缩放/位移动画。
- 大图预览中的辅助控件不能遮挡主体检查区域，优先贴右侧或角落。
- 图片处理的原图和结果图都在缩放工具条中提供底板切换，放在“联动”按钮左侧；点击后展开透明与纯色选项，默认透明底板。联动开启时，底板、缩放、移动和归位必须同步。

## 图片处理和拆图流程

- 拆图/命名的大图底部操作栏必须保持一行紧凑工具条：输入框上方显示短标签；尺寸适配方式用向上弹出的菜单选择，默认“自适应”；锁定比例用链条图标按钮放在宽高之间，不使用文字占位。
- 尺寸适配方式菜单在紧凑栏里只显示当前值和展开箭头，不重复显示“适配方式”标题；导出方式采用一个整体胶囊分段控件，切换时用滑块左右移动表达状态，不让页面背景闪黑。
- 导出页底部操作区避免重复展示导出对象、拆图状态、导出状态等 summary card；主要保留导出方式选择和操作按钮。
- 导入图片默认追加，不覆盖已有图片；只有明确清空时才移除已有图片。
- 支持粘贴导入，并提供显眼的粘贴按钮。无可粘贴图片时按钮视觉置灰，但可保留点击重试能力。
- 导入预览缩略图悬停时显示移除按钮，移除按钮要有提示。
- 抠图、拆图、命名、导出流程中的预览要尽量与最终导出一致。
- 拆图后的最终导出栏必须提供“导出到资源管理”入口，位置与“返回拆图/导出拆图结果”同一操作组。
- 拆图命名页的尺寸预设属于用户配置，新增或移除后必须跨浏览器重启保留；重置当前图片流程不能清空用户预设。
- 修改输出尺寸区域需要支持宽高比例联动，联动开启时编辑任一边都按当前比例同步另一边，输入布局不能因为联动控件而挤压重叠。
- 拆图导出清单里的每个预览卡片悬停时右上角显示移除按钮；点击只从当前导出清单移除该项，不删除原始图片或本地文件。
- 存储容量显示使用 `B / KB / MB`，不要把容量角标叠在图片预览上；预览下方元信息可以显示。
- 拆图导出结果需要尊重透明边缘处理，不因前端预览和后端导出路径不同而产生明显差异。
- 拆图分区识别优先产出单主体/单字级分区；当 alpha 连通域只得到整页大框时，必须启用基于背景色/视觉对比的保底切分，避免把整行或整张图当成一个分区。
- 视觉保底识别得到的分区若明显宽于或高于单主体比例，必须继续检查框内的低密度竖向/横向空隙并二次切分，避免横排或竖排相邻字因笔画粘连仍保留在同一分区。
- 拆图识别不能把同一字内部断开的笔画、部首或顶部小碎片单独拆成多个分区；生成最终框前必须按距离、投影交错和主体尺寸做碎片回收合并，再对过宽或过高合并框做二次切分。组件归行必须同时检查中心带、投影重叠和碎片尺寸，不能让位于两行之间的小碎片充当桥梁，把上下两个完整主体串成同一组。若两个区域距离较远且没有横向/纵向投影交错，不得仅因同色或同列就合并。
- 拆图识别必须提供“识别强度”配置：弱强度优先整体性，扩大碎片合并并减少二次切分；强强度优先细致度，降低最小识别面积并更积极拆开相邻主体。强度配置属于用户偏好，刷新后应保留。

## 视频处理流程

- 视频剪辑应接近专业工作台结构：素材区、预览区、参数区、时间线区清晰分工。
- 分割、多视频拼接、字幕等功能不能只做表单堆叠；需要有清楚的素材列表、片段列表、字幕列表和导出动作。
- 时间、片段、字幕操作要能从当前播放位置取值。
- 长任务要有进度反馈，不让用户猜测是否卡住。

## AI 创作与本地资料

- AI 图片、视频等生成能力使用独立一级页签“AI 创作”，不放进图片处理或视频处理的子页签。
- AI 创作内部按媒体类型组织；尚未接入的媒体入口可以显示为禁用并标记“待接入”，但不得进入空页面或展示不可用的假流程。
- 图片与视频生成共用任务和历史模型。任务提交后立即进入历史，等待、生成中、成功、失败和取消状态都需要持久化；刷新页面后应继续查询未完成任务。
- 所有成功结果先保存为 AI 原始资产，再由用户选择加入图片处理或视频处理。加入处理默认追加，不覆盖已有素材，也不修改历史原件。
- 历史支持单选和多选结果加入处理。删除历史时必须让用户明确选择“仅删除记录”或“删除记录及本地文件”；删除本地文件需要二次确认，且不影响已经导出到资源管理或外部目录的副本。
- AI 创作使用固定媒体工作台结构：媒体导航、生成参数、结果画布和任务队列分工清晰；结果卡与历史卡共用预览、加入处理、打开文件位置和删除语义。
- 本地工具不使用伪在线登录。顶部默认显示游客资料入口，点击后可修改本地头像、名称和 MCP Token。
- MCP Token 由网页提交给本地后端保存，前端不得持久化或回读完整 Token；界面只显示未配置、已配置或验证失败等状态，并提供测试连接与显式清除操作。
- 本地资料、Token、生成历史和生成文件保存在 `work/` 下，不得提交到 Git。Token 不得写入日志、错误信息、历史记录或前端状态快照。
- Token 未配置或验证失败时保留 AI 创作工作台，但禁用生成动作，并提供打开本地资料弹窗的配置入口。

## 后端和本地文件规则

- 本地文件夹绑定、资源扫描、导出路径选择等能力由后端提供轻量 API。
- 扫描本地文件夹必须设置上限，避免大目录卡死页面。
- 扫描应跳过隐藏目录、`__pycache__`、`node_modules` 等明显无关目录。
- 图片资源可通过本地预览 URL 展示；视频资源先登记为资源项，后续再细化视频预览。
- 不要把用户资源复制、移动或删除，除非功能明确要求且用户确认。

## 部署依赖与能力降级

- Git 仓库不应提交大型模型、模型缓存、外部二进制工具和虚拟环境；同事 clone 后必须能在“模型管理/运行环境”页看到缺失项。
- 模型管理页需要同时列出 AI 模型、外部图像组件、基础视频工具和 Python AI 依赖，并标明缺失项会影响哪些功能。
- 不需要下载的本地算法（例如 chroma key、Luma）要明确显示为本地算法，不要误导用户去下载模型。
- 功能入口使用到缺失模型或工具时，选项文本应降级显示，旁边要有“缺模型/缺工具/缺依赖”等胶囊提示。
- 点击缺失提示必须弹窗说明所需依赖，并提供前往模型管理页的动作；跳转后定位到对应依赖行，并高亮可操作按钮。
- 长下载必须显示进度，完成后要以实际可用性检查为准；若下载任务结束但缓存或工具仍不可用，必须显示失败或继续缺失，而不是显示已完成。

## 可访问性和交互

- 图标按钮必须有 `title` 和 `aria-label`。
- 可点击预览图使用按钮语义或键盘可达元素。
- 页面框选默认禁用，但输入框、文本域、可编辑区域必须允许选择文本。
- 编辑类弹窗按 `Escape` 或显式关闭按钮关闭；不要点击弹窗外遮罩关闭，避免误触导致输入丢失。
- 动画要短、清楚、辅助理解，不影响操作效率。

## 验证清单

每次生成或修改后，至少检查：

- 页面是否能访问：`http://127.0.0.1:8894/app/index.html` 返回 200。
- 前端语法：`node --check app\app.js`。
- 后端语法：改动 `server.py` 时运行 `.venv-ai\Scripts\python.exe -m py_compile server.py`。
- 样式空白：`git diff --check -- app\index.html app\app.js app\styles.css server.py`。
- 相关控件在桌面宽屏和窄屏下不重叠、不撑破。
- 如果新增后端 API，重启本地服务并探测接口。
