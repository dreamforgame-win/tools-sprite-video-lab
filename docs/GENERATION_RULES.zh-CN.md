# 灵帧工坊（Sprite Forge Lab）生成规范

> UI 视觉、黑白模式、胶囊页签、按钮、面板、弹窗等设计语言以 `docs/SUNNY_STAGE_DESIGN_LANGUAGE.zh-CN.md` 为准。任何 UI 风格调整先更新该设计语言文档和对应模板，再改实现。

这份文档是本项目后续 UI、交互和本地资源管理能力的生成基准。任何新功能、页面、控件或布局调整，先按这里实现；如果实际使用中发现规则不合适，优先修改本规范，再改代码。

## 工作方式

- 对外产品名称统一使用“灵帧工坊”或英文名“Sprite Forge Lab”。生成供应商名称只允许出现在对应的内部适配器、兼容接口和接入文档中，不得用作产品名、模块名、页面标题或用户配置项名称。
- 生成前先阅读本规范，确认要改的是哪一类界面或能力。
- 当前开发页面固定为 `http://127.0.0.1:8895/app/index.html`，对应代码目录为项目根目录 `F:\Codex-Program\sprite-video-lab`。除非用户明确要求查看归档，否则 UI、交互、AI 创作、本地资料等开发改动都应落在根目录。
- `.worktrees/ai-creation-workbench` 和 `http://127.0.0.1:8894/app/index.html` 仅作为迁移归档/参考，不作为当前开发验证目标。开始修改前必须核对目标端口和进程命令行，避免把改动落回旧 worktree 或 8894。
- 先沿用现有结构、类名、交互模型和视觉语言，不另起一套设计系统。
- 用户通过截图指出问题时，要判断问题属于“单次 bug”还是“规范缺口”。如果是规范缺口，先补充本文件。
- 每次交付需要说明改了哪些文件，以及是否需要刷新页面或重启后端。
- 验证按改动风险分级，并按“协作确认规则”在实施前说明是否测试、测试数量和范围；不得对低风险改动机械运行无关测试。
- 生成任务轮询期间只能增量更新对应任务的状态、进度和必要操作，不得周期性重建整个生成页面、风格列表、画布或详情面板；任务完成或失败时再进行一次结果级刷新，避免图片重复加载、界面闪烁和操作状态丢失。
- 长任务所在弹窗或浮层关闭后，原页面的任务入口必须继续显示当前状态与完成数/总数，并明确提供“查看进度”或“查看详情”动作；重新打开时必须恢复同一持久化任务，不得静默重复提交。状态轮询只增量更新该入口，任务成功后回落为常规创建入口，失败或收尾保存失败时保留可恢复入口。

## 界面风格

- 这是生产工具，不是落地页。首屏应直接呈现可操作界面，不做宣传式 hero。
- 布局优先紧凑、可扫视、可重复操作。避免大面积空白、重复大卡片、卡片套卡片。
- 对操作型工具，优先使用熟悉的控件：页签、分段按钮、图标按钮、色板、开关、输入框、列表、网格。
- 能用图形表达的控件不要写成长文字按钮；不常见图形必须有 `title` 和 `aria-label`。
- 同一导航或工具组内必须使用同一套线性图标语言，统一视口、描边粗细、端点和视觉尺寸；不得混用 Unicode 字符、实心三角、文本方块和不同字体自带符号来充当功能图标。
- 信息摘要默认做成一行状态条或 chip。只有需要对比多项大指标时才使用大 summary card。
- 页面级区域可以是全宽面板；重复资源、项目、结果项可以用卡片。
- 固定格式元素要有稳定尺寸，动态文字要省略或换行，不允许撑乱布局。
- 滚动范围要明确。管理台类页面优先让内容列表滚动，顶部操作区和上下文信息保持稳定。
- 列表、网格、方向导航等可滚动区域中的局部选择、详情打开/关闭、勾选、分组折叠和异步状态刷新，不得重置用户当前滚动位置。优先保留滚动容器本身并只增量更新选中态与详情；确需重建 DOM 时，必须在重绘前按容器记录滚动位置，并在重绘后恢复到有效范围内。
- 只有用户明确切换到不同数据上下文、应用会改变结果集合的筛选条件，或主动执行“回到顶部”时，才允许重置对应内容列表；同一次重绘中的其他独立滚动区域仍须保持原位置。新增列表/详情交互时必须覆盖“滚动到下方后操作不跳顶”的回归场景。
- 普通处理页允许页面滚动；只有明确要求固定工作台的模块才锁定页面滚动，并把滚动放到模块内部。
- 桌面端的 `视频转序列帧`、`视频处理`、`图片处理` 三个主工作台页签采用固定工作台滚动：顶部标题栏和左侧导航/信息区不随内容滚动，只有右侧内容模块滚动。
- 固定工作台内的步骤切换、跳过抠图、自动进入下一步等导航只能滚动模块内部内容区，不能调用整页滚动把内容重新顶到固定标题栏下方。
- 固定工作台里的左侧导航/信息区只能按内容自然高度排列，不允许为了填满工作台高度而拉伸导航项；内容超出时左侧区域自己滚动。
- 固定处理工作台的右侧滚动内容必须在四周预留稳定安全边距，并为滚动条单独预留空间；面板圆角、边框、投影和激活描边不得贴住或超出滚动裁剪边界。
- 固定处理工作台的步骤面板必须裁切内部标题背板和内容背景，内部白色或彩色背板不得越过父面板圆角；裁切不能影响面板自身投影和外部激活描边。
- 固定工作台窄侧栏中的按钮组必须允许子项按可用宽度收缩，不能继承会造成横向溢出的全局最小宽度；底部操作区与侧栏边缘之间必须保留内边距。
- 项目主导航和工作台内部的方向导航等长期占宽侧栏应支持从右侧分隔边缘折叠：鼠标悬停或键盘聚焦边缘热区时高亮完整分隔线并显示折叠/展开按钮，按钮必须具备明确的 `title`、`aria-label` 和展开状态语义。项目主导航折叠后只保留功能图标，方向导航折叠后只保留方向预览图和必要的图标动作；折叠不得改变当前选中项，确认状态应使用紧凑勾选标记，不得依赖被隐藏的文字。用户主动切换的折叠/展开状态属于临时界面偏好，必须在刷新后恢复；首次使用时默认展开。窄屏自动紧凑布局优先于已保存的手动展开状态。

## 项目与存储架构

- 应用首次打开进入一级项目总览，不直接进入某个生产或处理工具。一级项目总览至少提供 `Default` 项目、创建项目和打开已有项目。
- `Default` 项目固定使用 `work/projects/default/`，用于没有明确项目归属的临时工作；它不可删除，但允许清空或重置。
- `Default` 项目的注册路径必须跟随当前应用根目录自愈；如果 `work/project-registry.json` 里残留旧 worktree、旧盘符或不可用目录，启动时必须自动重定向回当前根目录的 `work/projects/default/`，不得在项目总览显示为“目录不可用”。
- 新项目默认以 `work/projects/` 为父目录，用户可以选择其他父目录。实际项目根目录使用英文 `slug` 子目录；项目显示名称可以使用中文，但目录名只允许小写英文、数字和短横线。
- 创建项目必须初始化版本化项目清单；打开已有项目必须识别 `.sprite-lab/project.json`，不能把任意非空目录静默初始化为项目。
- 项目业务数据不得保存在浏览器 `localStorage` 或 IndexedDB。浏览器只保留临时界面状态；项目元数据、资产树、生成历史、处理任务、文件版本、部署记录和回收站全部由项目文件夹承载。
- 本机应用配置可以保存最近项目路径、游客资料、MCP Token 和模型环境等全局设置，但不得保存项目资产正文。项目路径不可用时显示明确的离线/丢失状态。
- 进入项目后，项目是所有生成、处理、资产管理、项目对接和导出行为的根上下文。任何业务 API 都必须显式携带或解析 `projectId`，不得继续产生无归属资产。
- 项目目录至少区分 `.sprite-lab/` 元数据、`production/` 原始生产结果、`processing/` 处理结果、`library/assets/` 已入库资产、`exports/`、`cache/` 和 `trash/`。

## 项目工作台信息架构

- 进入项目后显示二级项目工作台。一级项目总览与项目内部的“项目总览”是两个不同层级，不得混在同一页面。
- 项目工作台一级节点为：项目总览、项目资产、资源库、回收站、项目设置。
- `项目资产` 是原 `AI 创作` 的升级名称，内部包含直接入口 `风格探索`，并按 `资产生产`、`资产处理` 两个同级分组组织后续工具。
- `资产生产` 只作为侧栏分组标题，不是可点击按钮；下级入口固定为 `图片生成`、`视频生成`、`音频生成`、`生成历史`。未接入能力可以禁用并标记“待接入”，所有生成结果自动进入当前项目的生成历史。
- `资产处理` 与资产生产同级，也只作为侧栏分组标题；下级按媒介提供图片处理、视频处理和后续音频处理。原视频转序列帧属于视频处理工具，不再作为项目外的独立业务模块。
- 资产生产和资产处理共享同一套资产结构树。生产结果加入处理时必须携带项目、资产节点、来源记录和版本关系；处理结果继续归属原资产节点。
- 图片资产生产常态采用“资产树 / 结果工作区”两栏结构，生成设置不长期占栏。只有选中具体资产后，用户点击结果区的“生成图片”按钮才打开右侧内缩浮层；结果详情也使用同一浮层位置，关闭后把空间完整还给结果区。浮层上、右、下使用一致的安全间距，只保留最外层浮窗底板，内部标题和滚动正文不得再叠加贯穿全高的白色底板或其他装饰底板。生成浮层复用风格探索已经稳定的生成交互：按“参考图 -> 提示词 -> 风格指导 -> 模型和参数 -> 高级设置”组织；参考图常态显示已选缩略图、数量/模型上限、本地添加和管理入口，完整候选使用按资产节点与来源分组的选择浮层。资产生产不再提供“资产描述”字段，生成数量保留且默认 1。模型、智能比例、分辨率格式和背景色块选择使用共享控件与能力约束；模型名称只在“模型和参数”的模型选框中显示，不在高级设置后方重复展示模型摘要或价格信息。资产生产背景仍保留透明、纯色和场景等生产语义，不强制套用风格探索背景集合。生成浮层不单独显示任务队列或常驻“服务配置”工具条；Token 未配置时只在必要提示中提供配置入口。等待、进行中、失败等任务状态由结果工作区和生成历史统一承载。
- 图片资产生产在提示词输入框正下方提供“选择提示词模板”入口。第一版模板为只读内置内容，按角色、场景、UI、图标、特效五类浏览；选择器必须支持分类切换、模板列表、完整提示词预览和显式应用，应用后替换当前提示词并允许继续自由编辑，不提供新建、编辑、保存或项目持久化。模板上的推荐模型只作为标签提示，不得自动切换当前模型。打开选择器时应按当前资产节点优先定位对应分类，无法识别时保留上次分类或回到角色类。
- 多视图与多方向角色模板使用稳定构图协议：三视图横向三列固定为“正面、侧面、背面”；四视图横向四列固定为“正面、左侧面、背面、右侧面”。四方向站立使用 3×3 九宫格，背面位于上中、左侧面位于中左、右侧面位于中右、正面位于下中；五方向使用左后方/背面位于左上/上中，左侧面位于中左，左前方/正面位于左下/下中；八方向依次为左后方/背面/右后方、左侧面/中心空/右侧面、左前方/正面/右前方。中心格始终留空，九宫格仅约束构图且成图不显示网格线、标题、箭头、罗盘或装饰文字；各方向角色比例、脚底基线和格内中心一致。多方向行走精灵图沿用对应外层九宫格，每个方向格内部承载相同帧数、相同尺寸和相同读取顺序的行走序列。提示词直接描述完整画面中的方向，不写“镜像”或“翻转”。
- 资产结构树中的分类和分组只负责组织与汇总浏览，只有 `asset` 类型的具体资产节点可以作为生成目标。选中分类或分组时，中央区域显示其子资产概览和包含后代的汇总结果，标题必须明确“下的全部结果”，每条结果标注实际归属资产；分类和分组不显示“生成图片”入口。选中具体资产时隐藏无意义的子节点空状态，使用完整层级路径标明当前资产，只显示该资产直属结果，并在结果标题栏显示“生成图片”按钮。分类和分组的数量统一显示“资产数 · 结果数”，具体资产只显示结果数量，不显示持久化“已选数”，不得再用无范围说明的单个数字。
- 历史数据中直接归属于分类或分组的生成结果必须通过幂等迁移归入该容器下的系统“未分类”资产；迁移前保留资产树和生成历史备份，只调整结果的 `asset_node_id` 与必要迁移元数据，不移动或删除生成文件，不改变记录 ID、生成时间、生命周期状态和来源关系。后端生成接口必须再次校验目标节点为具体资产，不能只依赖前端禁用状态。
- 图片资产生产的结果列表与画布必须复用风格探索的卡片结构、图片预览、临时多选、批量栏、右侧内缩详情浮层、分段右键菜单、右键选择规则和统一线性图标。具体资产结果区常态直接显示全部未回收结果并按最新时间排序，不额外占用一整行状态、类型、比例、背景、时间或排序筛选器。卡片主体单击打开详情，左上角复选框只承担临时批量选择，右上角悬停按钮打开大图，卡片底部不常驻操作按钮。完成结果常态不重复显示“已完成”“普通”“已选”或“已确认”，不直接展示任务 UUID；资产生产不提供“设为已选/取消已选”和“确认结果/已确认”业务动作，历史已有 `selected`、`confirmed` 数据不迁移并按普通成功结果展示；进行中、失败、已入库和回收站等仍影响可用操作的状态可按需显示。重新生成和生成相似图只打开并预填生成浮层，不立即提交。加入图片处理、加入资产管理、生成相似图、下载、打开位置和移入回收站等命令在列表、详情、画布和菜单中必须复用同一处理逻辑。
- 风格探索和图片资产生产的列表、画布空白区域右键必须提供当前上下文可用的创建入口。方向资源显示“生成图片 / 添加参考图”，指导图仓库显示“生成视觉指导图”，图片资产生产显示“生成图片 / 添加参考图”；图片资产生产的两个入口还必须同时出现在列表与画布共用的常驻工具区。只有具体资产节点可以执行图片资产生产动作，分类或分组上下文保留入口但真实禁用并说明原因。所有右键入口必须调用与页面按钮相同的处理逻辑，不得另建行为不同的快捷路径。
- 图片资产生产画布节点单击、键盘确认或右键选中后必须打开与风格画布一致的右侧内缩详情：生成结果节点复用结果详情，资产节点显示层级、类型和结果摘要，分类/分组节点显示组织信息。关闭节点详情或点击画布空白处时同步取消对应节点选中，但不得清除独立的批量结果勾选集合。
- `资源库` 拆分为同级节点：资产管理、项目对接。资产管理保存已筛选和确认的内部资源；项目对接承载正式项目目录绑定、路径映射、命名、格式转换、冲突处理和部署。
- 正式资源流转顺序为：资产生产 -> 资产处理 -> 资产管理 -> 项目对接 -> 正式项目文件夹。资产管理中的资源不能绕过项目对接直接部署。
- 从资产管理部署到正式项目默认采用复制/同步并保留源资产。已建立映射的资源可以原子备份后更新；来源不明的同名文件不得静默覆盖。
- 风格探索、图片生成和资产管理都必须提供列表与画布双视图；两种视图共享同一份项目文件数据，切换不得复制对象或丢失筛选、选中状态与业务状态。仅出现切换按钮但没有对应可操作视图不算完成。
- 风格探索中当前方向的内容层级固定为“方向摘要 -> 方向资源/指导图仓库 -> 当前页签工具”。方向资源与指导图仓库使用位于方向摘要中央的胶囊分段控件，不得放在方向操作之后或降级为内容区底部页签。列表/画布、生成图片、添加参考图和方向设置只属于方向资源，必须放在方向资源的上下文工具栏内；生成视觉指导图同时属于方向资源的生产入口和指导图仓库的仓库入口，两个页签都必须显示并复用同一套向导逻辑。列表/画布不得提升到风格探索页面标题栏，页签切换时不得继续显示另一页签的其他操作。
- 风格探索支持通过 `Ctrl+V` 粘贴图片。生成图片面板打开时，粘贴图片只加入本次生成的本地参考图，不得立即写入方向资源；其他状态下，粘贴图片立即导入当前方向，当前选中画布分组有效时加入该分组，否则进入未分组。输入框、文本域、下拉框和可编辑内容内不得拦截正常文本粘贴，且图片处理等其他模块原有的粘贴语义不得受影响。
- 风格探索中“方向”是唯一的一级容器，不再把“分组”作为独立业务结构暴露给用户。左侧列表显示风格方向；中间区域显示当前方向内的参考图、生成结果等内容；右侧显示当前选中内容的关联信息。列表与画布只是当前方向内容的两种表现形式，不得实现成两套互不一致的数据结构或交互流程。
- 风格探索画布节点必须由当前方向内仍有效的内容实时校验生成；参考图移除、生成结果移入回收站或业务状态变更后，画布不得继续显示对应的旧节点。参考图节点 ID 应基于文件路径等稳定来源，不得只依赖列表索引。参考图导入后显示名称默认使用用户上传时的原始图片名，且必须支持在详情面板中改名；落盘后的去重文件名只作为路径元数据，不得覆盖用户可见名称。
- 风格探索的列表选中内容切换到画布后必须同步为对应节点选中态；画布点击节点只允许局部更新选中态和右侧详情，不得重新读取或重载整个画布。
- 风格探索画布里的分组必须在列表视图中同步体现为内容分段；列表分段只读取同一份画布分组数据，不得另建一套列表专用分组结构。生成图片面板的参考图来源必须同时支持本地文件、当前方向已有图片和画布分组快捷选择；选择分组只作为批量选择参考来源，不得改变画布分组本身。
- 生成图片的参考图管理弹窗使用按分组组织的 16:9 大图网格，图片必须按原比例完整显示，不得裁切。候选卡左上角显示“参考图/生成结果”类型，底部遮罩显示名称，右上角复选框独立负责选择；点击图片主体只打开通用大图预览，不得同时改变选择状态。选中项需要明确描边，分组支持折叠/展开，折叠后仍显示该组已选数量和总数。
- 风格探索列表与画布必须使用同一套内容总数、选中集合和业务动作语义。画布中的“删除”对参考图和生成结果必须执行与列表一致的移除/回收站动作，不得只删除布局节点后又在重新加载时自动补回；便签等纯画布注释可以只删除画布节点。若未来支持仅隐藏布局节点，必须使用“从画布隐藏”等独立名称。
- 风格探索列表、画布、详情和右键菜单中的同一动作必须复用同一图标与命令处理逻辑；加入资产管理、移入回收站等与侧栏入口语义相同的动作还必须复用侧栏图标造型。查看大图、调整分组、移动/复制到方向和移入回收站属于列表与画布共用的内容操作；锁定、对齐、视口调整等空间操作只属于画布。
- 风格探索列表中的图片卡片必须支持拖拽调整画布分组：拖到具名分组即加入该组，拖到“未分组”即移出分组，拖回当前分组不产生变更。拖动时显示跟随指针的图片缩略图，并让当前目标分组整体呈现明确的背景和完整描边；不得再用“移到某组/移出分组”等文字标签重复提示或占用分组标题空间。拖动已多选图片时批量移动所选图片，否则只移动当前图片。分组变更必须直接写入列表与画布共用的画布节点数据并持久化，不得维护列表专用分组字段。
- 风格探索列表中的分组标题、便签、参考图、生成结果及其他具有有效共用动作的内容节点都必须拦截浏览器原生右键菜单，并显示与画布语义一致的自定义菜单；不得只给有图片或可拖拽卡片绑定右键菜单。菜单只显示当前对象与状态下真正可执行的动作：参考图和生成结果可复用查看大图、调整分组、移动/复制到方向及移除等内容动作；生成结果额外提供重新生成、设为封面、加入资产管理和下载，参考图额外提供重命名；便签提供编辑、调整分组和删除；未完成节点不得显示要求已有成品文件的动作。“调整分组”应列出当前方向已有分组、未分组和新建分组入口；菜单支持 `Escape` 和点击菜单外关闭，危险操作与普通操作需要明确分隔。
- 通用大图预览在图片属于明确业务分组时，必须携带该分组内全部可用图片并提供底部缩略图轨道、当前项标识和左右循环切换；方向资源使用列表/画布共用分组顺序，指导图仓库使用同一发布版本内的综合指导图、锚点图与模块图顺序。首尾切换必须闭环，点击缩略图与键盘左右方向键使用同一切换逻辑；切图后重置缩放与拖拽位置并让当前缩略图保持可见。无分组或组内只有一张图时不得显示空画廊控件。生成图片的完整提示词不得常驻占用大图底部，改由右侧工具栏中的提示词图标按需展开只读面板；切图时已展开面板保持打开并同步当前图片内容，移动端改为底部浮层。
- 右键菜单中的分组、移动目标等层级选项必须使用独立二级浮出菜单，不得在主菜单内部展开并改变主菜单尺寸。二级菜单默认向右展开，空间不足时自动换到左侧，并与主菜单统一响应 `Escape`、点击外部和视口变化关闭。
- 画布“适应”必须根据当前有效节点和分组边界计算视口位置与缩放，不得写死固定缩放值。常用工具在 1280px 桌面宽度下必须保持一行可见，不得依赖横向滚动条；无选中、无撤销记录等不可用动作要使用真实 `disabled` 状态。
- 选中整个画布分组时，右侧面板必须显示分组名称、节点数量和分组级操作，不能继续显示先前单个节点详情。分组名称在画布和列表分段中都要有可发现的编辑入口；列表分段支持折叠，便签要在列表中以注释内容体现，保证两种视图可理解同一份内容结构。
- 风格探索生成面板必须复用图片生成的模型能力约束：切换模型时同步更新其支持的比例、分辨率和参考图限制；无可用模型时禁用提交。面板顶栏直接显示“生成图片”，正文按“参考图 -> 提示词 -> 模型和参数”组织，不重复显示面板标题。参考图在生成面板常态只显示一行已选缩略图、已选/上限计数、本地添加和管理入口；完整分组与图片网格放入按需打开的选择浮层，不得把全部候选列表长期展开挤压生成参数。缩略图支持直接移除，选择浮层保留分组批选、单图选择和清空能力，提交/取消动作在长面板中保持可达。
- 风格探索生成面板的模型和参数区分两行：第一行只显示模型选择，第二行显示比例、分辨率和背景。字段直接使用选框呈现，不在选框上方重复“模型”“图片比例”“分辨率”“背景”等小标题，但必须保留可访问名称；分辨率选项统一显示为“分辨率 xK”。生成数量固定为 1，不显示生成数量和风格强度控件。
- 风格探索生成面板的背景固定提供“默认、洋红、绿幕、白底、黑底”。当前值和展开选项都必须显示对应色块，白底色块保留可辨认描边，“默认”使用中性棋盘色块。除“默认”外，选择背景时只在提交给远端图片模型的最终提示词中追加对应的纯色背景约束；提示词编辑框、生成记录和结果详情继续保存并显示用户原始提示词，不得外显自动追加内容。
- 常规点击“生成图片”打开风格探索生成面板时，参考图必须默认为空，不得自动全选当前方向参考图；重新生成、单图参考生图和分组参考生图等明确带来源的入口可以预填对应图片。画布分组右键菜单提供“以此为参考生图”，按画布顺序选取组内可用图片并打开生成面板；超过当前模型参考图上限时只预填前 N 张并明确提示截取结果。
- 所有图片生成入口的初始生成数量统一为 1；项目默认值、创建项目默认值和无显式设置时的回退值必须保持一致。图片比例列表默认提供“智能比例”：有参考图时读取第一张已选参考图的原始宽高比，并映射到当前模型支持的最接近比例；没有参考图时回退到 1:1。参考图选择或模型能力变化后，智能比例的显示值和最终提交值必须同步更新。
- 提交带参考图的生成任务时，本地项目路径不得直接传给远端模型。由 MCP 生成的图片必须保存并优先复用任务返回的远端素材 ID；本地导入图片必须先通过 MCP 素材上传接口取得素材 ID，并按文件指纹缓存复用。最终生成请求使用远端素材 ID 作为参考输入；素材解析或上传失败时必须阻止提交并显示明确错误，不得静默退化为纯文本生图。
- 生成历史快照中的参考图必须兼容旧版字符串路径和新版结构化对象；结构化对象以 `relative_path` 作为本地预览路径，并保留远端素材 ID、来源记录和文件指纹等追溯字段。详情缩略图、重新生成和历史恢复不得把结构化对象直接字符串化为 `[object Object]`，无有效本地路径的引用应明确过滤或降级提示，不得构造必然失效的文件地址。
- 风格探索任务轮询更新后，若任务属于当前方向，必须局部刷新当前列表、画布节点和右侧详情，不能只更新隐藏的图片生成模块。任务完成、失败或取消后，用户无需切换视图即可看到最新状态。
- 风格探索应支持候选内容并排对比、列表多选与批量操作，以及把参考图或生成结果移动/复制到其他方向。移动/复制后要同步更新源方向、目标方向、对应画布和当前选中状态；不得通过复制前端对象制造与项目文件不一致的临时数据。
- 风格探索的方向列表是侧栏导航，不得做成大卡片列表；方向项应紧凑、可扫视，选中态使用轻量高亮或竖条，不用整块大面积高饱和底色。风格探索已经在项目导航中提供明确入口时，工作台不再重复显示独立的中英文模块标题栏，首行直接呈现方向摘要与当前资源工具。中间内容区必须提供当前方向的添加入口，例如生成图片、添加参考图和方向设置；生成图片的模型、提示词、比例、分辨率、背景、负面提示和参考图等参数应在独立生成面板中配置。右侧详情/生成面板按需显示，顶栏直接使用“生成图片”“生成结果”“参考图”等当前模块名称，不显示“内容信息”这类泛化标题；未选中内容或未打开操作面板时应隐藏，让中间内容区获得更多空间。
- 列表/画布等互斥视图切换必须使用一个完整的胶囊分段控件，不得表现为两个彼此分离的矩形按钮；未选项保持白色控件底，选中项使用蓝色胶囊和对应深色底边。
- 双视图页面必须补齐对应字段清单中的筛选、详情和常用动作。画布视图不能只是空白坐标面板：风格画布需包含已保存方向并通过按钮打开生成设置，资产生产画布需保留结构树并仅在具体资产节点通过按钮打开生成浮层，资产管理画布需包含筛选与当前资产详情。
- 项目资产、资源库、回收站和项目设置这类固定项目工作台必须在顶栏、侧栏、状态栏之间保留稳定安全间距；模块外壳、标题栏、统计条、列表、详情栏和画布边框不得贴住视口边缘或被父级 `overflow` 裁掉。
- 固定项目工作台内部优先使用网格行列管理标题、摘要和内容区，不用固定像素高度加 `calc()` 强行扣减；当标题动作、统计项或筛选项换行时，内容区应自动让位且继续只在模块内部滚动。
- 项目工作台右侧详情、设置、部署、筛选等滚动容器必须预留底部内边距和稳定滚动条空间，底部按钮、文件输入、边框和圆角不能被状态栏或滚动条遮挡。
- 项目工作台详情栏里的文件名、路径、提示词等元信息必须在可用宽度内完整可读；窄面板中长文本应允许换行并使用 `overflow-wrap: anywhere`，不得用单行省略导致关键信息被裁掉。
- 文档字段清单中的条件字段也属于交付范围：项目比例必须支持自定义值，模板创建必须提供可浏览的模板说明；资产生产结果筛选必须包含状态、类型、比例、背景、时间和排序，画布快捷栏必须覆盖加入画布、变体、业务状态、标签、下载和删除。
- 风格方向和入库资产使用 `normal`、`selected`、`confirmed`、`archived`、`in_library`、`trashed` 中适用的状态；界面临时多选不得冒充持久化的“已选”业务状态。风格探索中已完成的生成结果在详情、内容列表和对比视图都不展示“结果状态”“业务状态”或对应标签，也不提供候选或确认结果操作；生成中的任务仍显示必要进度，后端仍可保留任务轮询、失败处理、入库和回收站所需的内部状态。
- 风格探索的生成结果详情按提示词、参考图、模型、时间自上而下展示；提示词使用只读信息行，不使用可编辑文本框，默认折叠并提供明确的展开/收起入口，避免占满详情面板。存在参考图时显示可打开大图的缩略图。主要动作是“重新生成”，点击后切换到生成图片面板、填入原提示词并只把当前结果作为参考图，不立即提交。设为封面、加入资产管理、下载和移入回收站使用带提示的紧凑图标按钮。
- 每个风格方向都可以独立拥有一个活动游戏美术指导包草稿和多个不可变发布版本；不再使用“确认唯一项目风格”或确认后自动归档其他方向的业务规则。每个指导包最多确认使用一个版本，新版本生成后不得自动替换当前确认版本。项目默认指导包只负责生产时预选方向，实际生产必须使用该包已确认的版本。
- 游戏美术指导包由必选的全局视觉基因和固定专业模块组成，专业模块第一版限定为场景与环境、角色与生物、UI / HUD、技能与 VFX、道具与装备。风格板用于人工理解、评审和导出，默认不得作为模型参考图提交。
- 资产生产只编译“全局视觉基因＋当前资产类型对应模块”，技能图标可额外引用精简 UI 规则；不得为了方便把全部模块和全部参考图一并提交。单次任务可以调整模块、参考图、风格强度和冲突处理，但不得回写已发布版本。
- 指导包运行时引用提供经济、智能平衡和精准三档。智能平衡为默认档，通常最多使用 2 张职责互补的参考图；实际数量还必须服从模型参考图上限。裁剪、素材失效和提示词冲突必须在提交前可见，精准模式无法满足必需参考时必须阻断。
- 指导包发布版本、生成时最终提示词、负面提示、模块列表、参考图职责、素材 ID、临时覆盖和告警都必须保存为不可变历史快照。资产生产只读取指导包明确确认的版本，不得静默回退到最新版本；重新生成默认复用原版本和快照，只有用户明确重新选择指导版本时才允许切换版本。
- 每个风格方向的指导包都可以生成视觉指导图，不以“确认风格”为前置条件。入口使用三步向导：选择参考图、选择生成模式与参数、生成并整理；顶部步骤使用连线圆形数字节点，已完成步骤可以回看，未完成步骤不可越级。
- 视觉指导图参考图常态只显示紧凑摘要，完整素材选择使用独立二级弹窗并复用当前方向的画布分组、批量选择和通用大图预览；异步加载或分组变化后，已打开的二级弹窗必须就地刷新，并保留滚动位置、分组展开状态、已选状态和当前弹窗层级，不得因整块重建 DOM 跳回顶部或关闭弹窗。参考图由 MCP 生成且已有远端素材 ID 时直接复用，不得重新上传。
- 视觉指导图支持“整体生成”和“分模块生成”。整体模式只调用一次图片模型并由本地整理模板；分模块模式按“视觉基因锚点图 → 已选专业模块图 → 本地整理模板”顺序执行，视觉基因固定启用，五个专业模块默认全选且可调整。每个远端节点固定只生成 1 张图。
- 视觉指导图必须显式提供“精简（小游戏推荐）/ 标准 / 丰富（概念展示）”三档细节密度，默认使用精简档。细节档位属于生产规格而非装饰偏好，必须进入提示词预览、正式运行、输入签名、运行恢复和发布后的指导包编译；旧运行未记录档位时按精简档兼容。精简档以手机 720p/1080p 游戏画面和约 96–128px 资产显示尺寸为验收尺度，优先轮廓、功能和大色块，每个主体约 2–3 个主要形体块、主要材质不超过 2 种、标志性装饰不超过 1 个；参考图只继承媒介、色板和形状语言，不继承过量表面细节。场景限制道具密度并保留清楚通道，角色限制衣褶和配件，UI 使用大触控区和粗边框，技能特效使用单一核心形状与有限粒子，道具优先功能轮廓。负面约束必须定向限制密集雕花、细碎纹理、重复小图案、过多挂件、磨损颗粒、微小刻痕和无生产价值的局部特写；精简档不得继续要求“多个样例和局部放大”。
- 图片模型只负责生成无标题、无标签、无可读文字、无伪文字和无水印的视觉内容；准确中文标题、模块名和色板由本地模板排版器绘制。提示词预览必须使用独立查看弹窗，预览本身不得创建运行记录、文件或远端任务。
- 视觉生成运行、动态节点、失败信息、输入签名、参考素材快照和 MCP 素材 ID 必须持久化。关闭向导或刷新页面后运行继续，重新打开时可恢复；失败图片节点支持单独重试，本地模板失败的重试不得再次调用图片模型。输入发生变化后旧结果立即失效，不得写入当前草稿。
- 视觉指导图运行全部成功后自动固化为新的不可变指导版本并进入“指导图仓库”，默认未确认使用；同一次固化还必须在对应风格方向画布中，把本次远端生成的锚点图/模块图或整体图自动建立为一个持久化分组，名称使用“指导包标题 + v版本号”。自动分组必须幂等，不重复创建节点或分组，并将新组放到既有内容之外。部分节点失败时不得创建半成品版本；图片已生成但版本固化失败时必须保留结果并提供仅重试保存版本的操作，不能要求重复付费生成。重新生成锚点图时，其下游模块图和模板必须失效并按依赖顺序重新生成。
- 视觉指导图从“生成设置”提交到远端运行创建完成之间属于独立的阻塞提交阶段。点击开始后必须立即锁定当前向导并显示覆盖式等待反馈，明确说明正在准备参考图和连接生成服务，首次使用的参考图可能需要上传；同一次提交未结束前不得重复创建运行或继续修改设置。请求成功后自动进入生成进度，请求失败后撤销锁定、保留用户设置并显示错误。生成进度中的 `submitting`、`queued`、`running` 活动节点需要持续但克制的动画反馈，终态节点停止动画，所有状态使用中文并遵循减弱动效偏好。
- 视觉指导图的父运行状态必须由全部子节点实时聚合：只要任一远端节点仍处于 `submitting`、`queued` 或 `running`，父运行就继续视为生成中，活动状态优先于其他节点的失败状态；只有不存在活动节点时才允许把父运行收敛为失败。前端恢复和轮询也必须以“父运行生成中或任一子节点活动”为继续条件，不能因持久化父状态暂时过期而停止对子节点的核对。
- 视觉指导图运行创建后，三步向导的“选择参考图 / 生成设置 / 生成指导图”页签必须始终允许往返查看，不得把已建立的运行进度页再次锁成不可进入。运行处于生成中或取消中时，参考图、模式、细节密度、模块、模型和参数统一只读锁定，预览参考图和查看提示词仍可用；当前运行到达成功、失败或已取消终态后才解锁设置并允许创建新运行，活动运行期间不得出现第二个提交入口。
- 视觉指导图必须支持持久化取消请求。当前生成供应商不提供远端任务取消能力时，界面必须明确说明“取消”只会停止尚未提交的后续节点，已经提交的远端任务可能继续完成并计费；后端在收到取消请求后不得再提交新节点或生成本地模板，也不得发布半成品版本，但必须继续核对已提交节点直至终态，再把父运行收敛为已取消。已完成图片与生成历史保留，不因取消删除；取消完成后允许使用原设置重新生成。
- 同一视觉指导图运行批量提交专业模块时，若某次提交已经确认是 Token、余额、额度或月度预算等共享账户约束错误，必须立即停止后续远端提交，并把尚未提交的下游节点标记为可重试失败；不得继续制造内容相同、必然失败的生成历史记录。已提交或已成功的兄弟节点保持原状态，用户后续可以逐节点重试。
- 视觉指导图远端节点仍需写入全局生成历史以支持追溯、诊断和重试；但方向资源只展示其中已成功且有可用图片的记录，失败、取消或仍在排队的内部节点不得显示为方向图片卡。普通图片生成记录继续按原有状态规则展示，不得用这一过滤隐藏普通生成失败。
- 风格方向主内容区使用“方向资源 / 指导图仓库”两个页签。方向资源保留列表、画布和分组；指导图仓库按版本分组，确认使用版本固定置顶，其他版本按完成时间倒序。默认展开确认使用版本和最新版本，其余折叠；每组保留综合指导图、视觉基因锚点图和所选专业模块图。第一版不提供删除版本。
- 视觉指导图的新运行固化为新版本时，草稿中的运行生成型引用必须以本次运行结果替换此前视觉运行产生的引用，不得把上一版本的锚点图、整体图或模块图继续继承到新版本；用户人工添加且不属于视觉运行的参考图必须保留。每个已发布版本只展示自身运行的生成资源，历史版本快照保持不变；指导图仓库与方向资源中的同版本内容必须来自同一次视觉运行。
- 原独立指导包编辑工作台不再作为风格探索主流程入口；原编辑按钮统一改为“生成视觉指导图”并直接打开三步向导。仓库图片使用通用悬停大图入口。缺少多模态分析能力不能阻断视觉指导图生成、版本确认和资产生产引用。删除风格方向时，其活动指导包必须同步移入回收状态或与方向脱离；若它是项目默认项则立即清空默认，不得自动替换成其他包。
- 画布至少支持缩放、平移、节点拖动、多选、删除、分组、便签、锁定、撤销与重做，并把节点位置、尺寸、层级、锁定状态和视口保存到项目文件夹。画布基础手势不使用“选择/框选”工具模式：左键空白区域直接框选并显示框选区域预览，左键节点选中或拖动节点，中键拖动画布视口；节点拖动过程中连线和分组框必须实时跟随刷新。便签必须支持编辑。分组框本身必须可拖动，拖动分组等同于拖动组内全部未锁定节点；分组名称必须持久化并支持编辑。自动整理/对齐属于常驻可用命令：无选择时整理全部未锁定内容，有选择时只整理所选内容；分组作为整体单位处理，锁定节点保持原位，整理后节点和分组之间不得互相压叠。当明确选中分组执行对齐时，组内节点按方阵优先网格整理，数量容量依次采用 1x1、2x2、3x3……，不足满格时保持从左到右、从上到下排列；已有分组与未分组节点合并时优先沿用已有分组名称，多个分组合并时沿用选中顺序中的第一个分组名称。任何新加入画布的内容节点或便签必须先寻找不与现有节点重叠的空位，不能使用固定坐标或仅按内容索引推算位置。
- 风格探索和资产管理的三栏画布工作台是一个连续面板：圆角只属于最外层工作台外壳，左侧上下文栏、中间画布和右侧设置栏之间使用直角边界与分隔线，不得给内部列重复添加圆角或卡片间隙。风格探索按需出现的内容详情不作为固定第三栏，应以内缩浮窗覆盖在内容区右侧，上、下、右保留稳定安全边距，并使用完整边框、圆角和轻投影；浮窗只能覆盖列表或画布的主内容区域，不得遮挡方向摘要、页签/视图工具栏以及画布底部状态栏。右上角必须提供关闭按钮，关闭等同于取消当前内容/画布对象选中，但不得清除独立的批量勾选集合。
- 画布专属工具不固定占用整行菜单。内容组织操作使用画布内左上悬浮工具组；撤销、重做、缩放比例和适应画布使用左下悬浮工具组。悬浮控件不得遮挡节点主要内容，纯图标按钮使用固定正方形尺寸。
- 画布悬浮工具按钮常态使用白色控件底；撤销、重做、缩放、适应和未生效的编辑命令不得在常态下整排显示为蓝色。选择和框选属于固定基础手势，不得再提供独立模式按钮。
- 节点、分组或框选集合变化后，悬浮工具的可用状态必须立即局部刷新；不得出现对象已选中但分组、对齐等按钮仍保持禁用，或需要再次点击、重绘画布后才更新的滞后状态。
- 列表与画布都支持按对象区分的右键菜单：分组在两种视图共用重命名、选择组内内容、以组内图片为参考生图、移动/复制和解除分组等适用动作，画布再补充网格排列与锁定等空间操作；便签在两种视图共用编辑与删除，并在存在分组数据时支持调整分组；画布空白区域提供新建便签、全选和适应画布。重要或不易发现的节点操作还要在右侧详情面板提供入口，不能只依赖右键菜单。
- 删除风格方向、资产节点、生成结果或入库资源时默认进入项目回收站。回收站必须支持单项/批量恢复、单项/批量彻底删除和清空；危险操作二次确认。
- “彻底删除”必须清除对象清单记录和仍位于项目目录内的对应文件；不得只删除回收站索引而遗留不可见业务文件。
- `项目设置` 是项目元数据和默认生产参数的编辑入口，至少包含基础信息、默认生成参数、风格设置和数据管理。模型运行时管理是独立工具，不能借用“项目设置”名称。
- `资产管理` 与 `项目对接` 必须使用独立页面和独立后端契约。资产管理负责确认、筛选、标签、预览和下载；项目对接负责目标目录、分类映射、冲突预检、备份、部署和验证。

## 自动化与接口优先

- Web UI、CLI、REST API 和后续本地 MCP 适配器必须共用同一套后端领域服务；不得把关键业务状态或流转逻辑只写在前端事件处理器中。
- “AI 可以不操作网页而完成项目生产、处理、入库和正式装配”是架构验收条件，不是后续可选扩展。
- 长任务使用持久化异步任务和稳定任务 ID，支持轮询、恢复、重试和事件读取。API 必须支持幂等键，避免 Agent 重试造成重复项目、重复生成或重复部署。
- 每次自动化执行建立 `workflowRun`，记录操作者、原始需求、步骤、输入输出、模型与参数、文件哈希、版本、错误、重试、确认和时间戳。
- 正式项目文件必须能反向追溯到部署记录、资产管理版本、处理任务、生成结果以及原始提示词/参考资源。
- 项目修改需要项目级锁、原子写入、清单版本号和迁移机制。部署前必须执行路径、格式、命名和冲突预检，部署后必须验证目标文件存在且格式有效。
- 后端接口采用版本化 JSON 契约，并维护项目格式、API、资产生命周期、自动化工作流、项目对接和 MCP 工具文档。
- `workflowRun` 不能只有创建动作；必须支持列表、读取和状态回写。运行状态至少包含 `planned`、`running`、`succeeded`、`failed`、`canceled`，步骤需保存输入、输出、错误、重试次数及开始/结束时间。
- 自动化能力至少提供 REST API 和可执行 CLI 两种入口。CLI 直接调用领域服务，不通过浏览器自动化，也不能维护另一份业务状态。

## 资源库与项目对接规则

- 原资源管理页的项目创建和项目切换能力迁移到一级项目总览；资源库始终工作在当前项目上下文中。
- 项目总览页只展示项目卡片和项目级操作，不同时展示资源列表，避免项目列表和资源内容互相挤占空间。
- 项目总览卡片的最右侧主动作必须是进入项目，使用黑底主按钮；改名和删除收进“修改/项目设置”弹窗，删除不得直接暴露在卡片操作行。
- 项目总览卡片的标题栏、说明和底部路径行必须允许内部列收缩；长项目名、说明和绝对路径使用省略号，不得把状态标签、进入项目动作、边框或背景撑出卡片范围。
- 项目资源详情页采用左右布局：左侧放返回、项目信息、项目操作、绑定文件夹状态和子文件夹页签；右侧只显示资源内容。
- 详情页侧栏中的按钮、输入框、页签和信息块不能贴住面板边缘，必须用内边距和间距隔开。
- 详情页不显示“收集抠图结果/收集拆图清单”这类临时收集按钮；文件夹未绑定时只显示“绑定文件夹”，绑定后显示已绑定文件夹列表、左侧短按钮“添加”和右侧长按钮“刷新文件夹资源”。
- 绑定文件夹支持多个路径。状态不再单独显示“已绑定/未绑定”提示块，状态通过绑定数量、路径列表和按钮文案表达。
- 项目内资源分两类：
  - 项目收集资源：抠图结果、拆图清单、后续导出物等。
  - 绑定文件夹资源：来自本地绑定文件夹的扫描结果。
- 图片结果等导出模块需要支持“导出到资源管理”：点击后使用项目选择弹窗选择目标项目，资源写入所选项目，不自动切换当前资源管理页面或当前项目。
- 拆图命名页调整输出尺寸后，“导出到资源管理”必须以当前导出清单的输出尺寸、缩放模式和裁剪/整图区域为准；同一资源再次导出到同一项目时要更新已有条目，不能因去重保留旧尺寸或旧预览。
- 项目收集资源移动到绑定文件夹时，必须把资源元数据中的裁剪区域和输出尺寸渲染成实际落盘文件；移动完成后文件夹扫描显示的尺寸应与导出尺寸一致，不能退回原始素材尺寸。
- 绑定文件夹是引用和展示，不默认复制文件。是否复制入库要作为后续明确功能设计。
- 资源预览区支持框选资源；框选只在资源网格区域内生效，不能影响缩略图预览按钮、文件夹折叠按钮和弹窗交互。框选采用切换语义：框到未选中资源时选中，框到已选中资源时取消，框外资源保持原状态。
- 文件夹资源必须保留层级。展示时按一级子文件夹归类：
  - 页签第一项为 `全部`。
  - 后续页签为 `项目资源`、`根目录`、各一级子文件夹。
  - `全部` 页签按文件夹分段显示。
  - 每个分段第一行只显示文件夹标题、箭头和数量。
  - 分段可展开/折叠；折叠时只保留标题，不显示预览图。
  - 展开时第二行开始显示预览图网格，然后接下一个文件夹分段。
  - 空文件夹也必须显示分段；展开时预留一行高度，并在中间显示“文件夹为空”。
- 资源列表区域自己滚动，项目标题、操作按钮、绑定文件夹状态和页签不随资源滚走。
- 资源管理页禁止整页滚动，且仅在资源管理页激活时锁定页面；项目总览只让项目卡片网格滚动，详情页只让左侧文件夹页签和右侧资源列表滚动。
- 资源列表区不重复显示大标题或说明文案；当项目标题和状态栏已提供上下文时，资源区顶部只保留页签和必要工具。
- 资源卡片保留稳定尺寸，文本区位置固定；预览图只在上方预览框内按资源原始比例缩放，以短边适配框内显示，不允许裁剪主体或撑开卡片。
- 带 `crop` 信息的项目资源必须按裁剪区域生成缩略图和大图预览，不能直接展示原始整图导致多个拆图资源看起来相同。
- 资源卡片至少显示来源类型、文件名、尺寸或路径摘要。

## 图片预览和透明底板

- 风格探索、图片生成、资产管理、项目设置等所有图片型内容都必须接入统一的大图预览能力；列表、画布、详情面板中的预览入口应打开同一个全屏 lightbox，不得各自实现尺寸较小且行为不一致的预览弹窗。
- 缩略图、详情预览和画布节点预览的显示区域可以保持固定尺寸，但图片本身必须按原始比例完整自适应显示；除非用户明确要求裁切，不得使用会截断主体的 cover 展示。
- 图片主体常态不额外占用“查看大图”文字按钮；所有缩略图的图片主体本身必须是可点击、键盘可达的大图入口，鼠标悬停或键盘聚焦时在图片角落显示统一的放大图标作为提示。主体和提示图标打开同一个通用 lightbox，不得形成嵌套按钮；缩略图与 lightbox 都按原始比例完整自适应显示。入口必须具备明确的 `title` 和 `aria-label`。
- 画布节点预览必须让图片元素自身按原始比例缩放并居中，不得把 `<img>` 拉满宽高后只依赖 `object-fit` 在元素内部绘制，避免透明/纯色背景图在宽扁节点里视觉偏移；节点标题区必须限制高度，不能挤压预览区。
- 九宫格处理界面的处理面板、结果预览面板、画布背景和图片背景必须同步响应大图预览的透明/纯色底板设置；透明模式显示棋盘格，纯色模式使用当前底板颜色。
- 九宫格透明/纯色底板只作用于图片检查区域和预览框内部，预览框以外的面板背板、边框和工具区保持默认工作台样式。
- 九宫格线参数输入表示线条到对应边缘的距离：左/上为距左上边缘，右/下为距右下边缘；线贴边时参数为 0，拖拽和输入必须保持同一语义。
- 九宫格结果预览按实际像素尺寸显示：结果图尺寸小于预览区可用宽高时用 1:1 显示，超出时才按比例自适应缩小。
- 大图预览必须支持透明底板和不透明底板。
- 大图预览在图片放大并超出可视边界后必须支持鼠标与触控拖动平移，使用指针捕获保证拖动连续；平移范围按当前缩放比例和可视区域实时钳制，使图片各边可以被检查但不能把主体完全拖出视口。缩回 1 倍、切换图片或关闭预览时自动复位，窗口尺寸变化时重新钳制；放大态使用抓手光标，拖动时使用抓取光标，并保持滚轮缩放、命名、九宫格和底板设置可用。
- 不透明底板默认白色，并可通过色板改色。
- 底板工具条使用胶囊形图标控件：
  - 棋盘格图标表示透明底板。
  - 实心方块表示不透明底板。
  - 色板圆点直接填充当前底板颜色。
- 色板只在不透明模式下显示。切到透明模式时收回，切回不透明时弹出，需要有缩放/位移动画。
- 大图预览中的辅助控件不能遮挡主体检查区域，优先贴右侧或角落。
- 图片处理的原图和结果图都在缩放工具条中提供底板切换，放在“联动”按钮左侧；点击后展开透明与纯色选项，默认透明底板。联动开启时，底板、缩放、移动和归位必须同步。

## 图片处理和拆图流程

- 拆图/命名的大图底部操作栏必须保持一行紧凑工具条：输入框上方显示短标签；尺寸适配方式用向上弹出的菜单选择，默认“自适应”；锁定比例用链条图标按钮放在宽高之间，不使用文字占位。
- 尺寸适配方式菜单在紧凑栏里只显示当前值和展开箭头，不重复显示“适配方式”标题；导出方式采用一个整体胶囊分段控件，切换时用滑块左右移动表达状态，不让页面背景闪黑。
- 导出页底部操作区避免重复展示导出对象、拆图状态、导出状态等 summary card；主要保留导出方式选择和操作按钮。
- 导入图片默认追加，不覆盖已有图片；只有明确清空时才移除已有图片。
- 支持粘贴导入，并提供显眼的粘贴按钮。无可粘贴图片时按钮视觉置灰，但可保留点击重试能力。
- 导入预览缩略图悬停时显示移除按钮，移除按钮要有提示。
- 抠图、拆图、命名、导出流程中的预览要尽量与最终导出一致。
- 拆图后的最终导出栏必须提供“导出到资源管理”入口，位置与“返回拆图/导出拆图结果”同一操作组。
- 拆图画布底部工具栏的自适应、居中、添加、删除、合并等纯图标操作必须使用统一线性图标和固定正方形点击区域，不得继承文字按钮最小宽度而拉成长条；透明/纯色底板使用完整胶囊分段控件，当前模式为蓝色激活态。
- “确认拆图”属于正向流程确认，启用时使用绿色主按钮；不可确认时使用中性禁用底、禁用文字和真实 `disabled` 状态，不得保留绿色投影或显示为黑色可操作按钮。
- 拆图命名页的尺寸预设属于用户配置，新增或移除后必须跨浏览器重启保留；重置当前图片流程不能清空用户预设。
- 修改输出尺寸区域需要支持宽高比例联动，联动开启时编辑任一边都按当前比例同步另一边，输入布局不能因为联动控件而挤压重叠。
- 拆图导出清单里的每个预览卡片悬停时右上角显示移除按钮；点击只从当前导出清单移除该项，不删除原始图片或本地文件。
- 存储容量显示使用 `B / KB / MB`，不要把容量角标叠在图片预览上；预览下方元信息可以显示。
- 拆图导出结果需要尊重透明边缘处理，不因前端预览和后端导出路径不同而产生明显差异。
- 拆图分区识别优先产出单主体/单字级分区；当 alpha 连通域只得到整页大框时，必须启用基于背景色/视觉对比的保底切分，避免把整行或整张图当成一个分区。
- 视觉保底识别得到的分区若明显宽于或高于单主体比例，必须继续检查框内的低密度竖向/横向空隙并二次切分，避免横排或竖排相邻字因笔画粘连仍保留在同一分区。
- 拆图识别不能把同一字内部断开的笔画、部首或顶部小碎片单独拆成多个分区；生成最终框前必须按距离、投影交错和主体尺寸做碎片回收合并，再对过宽或过高合并框做二次切分。组件归行必须同时检查中心带、投影重叠和碎片尺寸，不能让位于两行之间的小碎片充当桥梁，把上下两个完整主体串成同一组。若两个区域距离较远且没有横向/纵向投影交错，不得仅因同色或同列就合并。
- 拆图识别必须提供“识别强度”配置：弱强度优先整体性，扩大碎片合并并减少二次切分；强强度优先细致度，降低最小识别面积并更积极拆开相邻主体。强度配置属于用户偏好，刷新后应保留。

## 视频处理流程

- 视频剪辑应接近专业工作台结构：素材区、预览区、参数区、时间线区清晰分工。
- 分割、多视频拼接、字幕等功能不能只做表单堆叠；需要有清楚的素材列表、片段列表、字幕列表和导出动作。
- 时间、片段、字幕操作要能从当前播放位置取值。
- 长任务要有进度反馈，不让用户猜测是否卡住。

## 项目资产与本地资料

- 原独立一级页签“AI 创作”改为项目内的“项目资产”。图片、视频和音频生成归属资产生产；图片、视频和音频处理归属同级的资产处理。
- 项目资产内部先按风格探索、资产生产、资产处理组织，再在生产或处理页面按媒体类型组织；不得把媒体类型错误提升为业务一级节点。
- 图片与视频生成共用任务和历史模型。任务提交后立即进入历史，等待、生成中、成功、失败和取消状态都需要持久化；刷新页面后应继续查询未完成任务。
- 所有成功结果先保存为生产原始资产，再由用户选择加入图片处理或视频处理。加入处理默认追加，不覆盖已有素材，也不修改历史原件。
- 历史支持单选和多选结果加入处理。删除历史时必须让用户明确选择“仅删除记录”或“删除记录及本地文件”；删除本地文件需要二次确认，且不影响已经导出到资源管理或外部目录的副本。
- 资产生产使用固定媒体工作台结构：媒体导航、资产结构树和结果画布分工清晰；生成参数与结果详情使用按需右侧内缩浮层，不长期占用固定栏。任务提交后直接进入结果工作区与生成历史，不额外占用独立任务队列面板。结果卡与历史卡共用详情、预览、加入处理、打开文件位置和删除语义。
- 资产生产的分类与分组节点只承担组织、创建入口和结果汇总，不显示具体资产专属的生成入口或生成设置。父级节点内容区采用“子节点导航 / 全部结果”左右布局：子节点栏使用与资产结构树接近的固定窄宽度，子节点卡片单列紧凑排列；栏顶部固定上下文创建入口，列表独立滚动，创建完成后自动切换到新资产节点。汇总结果按实际资产节点分组，并复用风格探索列表的折叠、整组选中、卡片详情、卡片预览、批量操作和右键菜单规则。具体资产叶子节点只常态显示结果列表，通过标题栏按钮打开生成浮层；窄屏时父级左右布局回落为上下布局。
- 本地工具不使用伪在线登录。顶部默认显示游客资料入口，点击后可修改本地头像、名称和 MCP Token。
- MCP Token 由网页提交给本地后端保存，前端不得持久化或回读完整 Token；界面只显示未配置、已配置或验证失败等状态，并提供测试连接与显式清除操作。
- 本地资料和 Token 保存在应用 `work/` 配置中；生成历史和生成文件保存在对应项目目录中，不得提交到 Git。Token 不得写入日志、错误信息、历史记录、项目清单或前端状态快照。
- Token 未配置或验证失败时保留项目资产工作台，但禁用生成动作，并提供打开本地资料弹窗的配置入口。

## 后端和本地文件规则

- 本地文件夹绑定、资源扫描、导出路径选择等能力由后端提供轻量 API。
- 扫描本地文件夹必须设置上限，避免大目录卡死页面。
- 扫描应跳过隐藏目录、`__pycache__`、`node_modules` 等明显无关目录。
- 图片资源可通过本地预览 URL 展示；视频资源先登记为资源项，后续再细化视频预览。
- 不要把用户资源复制、移动或删除，除非功能明确要求且用户确认。

## 部署依赖与能力降级

- Git 仓库不应提交大型模型、模型缓存、外部二进制工具和虚拟环境；同事 clone 后必须能在“模型管理/运行环境”页看到缺失项。
- 模型管理页需要同时列出 AI 模型、外部图像组件、基础视频工具和 Python AI 依赖，并标明缺失项会影响哪些功能。
- 不需要下载的本地算法（例如 chroma key、Luma）要明确显示为本地算法，不要误导用户去下载模型。
- 功能入口使用到缺失模型或工具时，选项文本应降级显示，旁边要有“缺模型/缺工具/缺依赖”等胶囊提示。
- 点击缺失提示必须弹窗说明所需依赖，并提供前往模型管理页的动作；跳转后定位到对应依赖行，并高亮可操作按钮。
- 长下载必须显示进度，完成后要以实际可用性检查为准；若下载任务结束但缓存或工具仍不可用，必须显示失败或继续缺失，而不是显示已完成。

## 可访问性和交互

- 图标按钮必须有 `title` 和 `aria-label`。
- 可点击预览图使用按钮语义或键盘可达元素。
- 页面框选默认禁用，但输入框、文本域、可编辑区域必须允许选择文本。
- 编辑类弹窗按 `Escape` 或显式关闭按钮关闭；不要点击弹窗外遮罩关闭，避免误触导致输入丢失。
- 动画要短、清楚、辅助理解，不影响操作效率。

## 协作确认规则

- 任何实现性修改、数据迁移、依赖调整或本地服务操作开始前，必须先向用户简要复述需求理解、关键布局或交互变化，并补充必要假设；复杂方案可以先用示意图表达。
- 每次请求实施确认必须明确标注验证等级、是否需要测试、测试内容数量和测试范围；免测改动也要明确写出“无需测试”。
- 在用户明确确认前，只进行讨论和必要的只读检查，不编辑项目文件、不修改数据、不重启服务，也不提前实现部分方案。
- 用户确认后再开始实施；若实施过程中发现会明显改变已确认范围的新问题，应先说明影响并再次确认，不自行扩大改动范围。

## 分级验证规则

- `L0（免测）`：文档规范，以及不改变布局结构、交互逻辑或数据的纯文案、图标、颜色、间距、描边等简单界面处理。无需测试，只核对改动内容；不启动浏览器验证，也不运行测试命令。
- `L1（轻量验证）`：局部布局变化或简单交互调整。验证 2–5 个直接相关场景，不运行无关模块测试。
- `L2（标准验证）`：涉及前端共享状态、持久化、任务状态或多个关联操作。验证 6–12 个相关场景，并运行对应自动化测试。
- `L3（完整回归）`：涉及后端、API、数据迁移、文件操作或核心跨模块流程。执行完整相关回归和关键路径冒烟测试；实施确认时根据影响范围列出具体测试数量。
- 实施过程中若风险高于已确认等级，必须暂停并按新的等级、测试数量和范围再次确认。

## 验证清单

以下检查按已确认的验证等级和实际改动范围选用，不要求每次全部执行：

- 页面是否能访问：`http://127.0.0.1:8895/app/index.html` 返回 200，并确认该端口进程来自根目录 `server.py`。
- 前端语法：`node --check app\app.js`。
- 后端语法：改动 `server.py` 时运行 `.venv-ai\Scripts\python.exe -m py_compile server.py`。
- 样式空白：`git diff --check -- app\index.html app\app.js app\styles.css server.py`。
- 相关控件在桌面宽屏和窄屏下不重叠、不撑破。
- 如果新增后端 API，重启本地服务并探测接口。
