# AI 生图抠图、拆分与分层工作流方案

> 状态：设计提案，尚未实现。本文记录目标架构、候选技术和验收边界，不代表当前产品已经具备对应模型或接口。

## 目标

把生图结果处理从“依赖纯色背景的单一路径”升级为可协商、可降级、可审计的分层处理工作流，使同一套项目数据能够覆盖：

- 已带透明通道的原生图片；
- 纯色背景图片的快速色键抠图；
- 复杂背景、柔边、玻璃、烟雾和光效的 AI Alpha Matting；
- 多对象图片的框选或自动检测、逐对象抠图和拆分；
- UI 设计图的坐标、尺寸、层级、命名与引擎重建信息；
- Agent 原生处理、本地模型处理和服务端 MCP 处理的能力协商。

第一阶段不从零训练私有模型。优先使用开放模型验证完整链路，同时保留现有本地色键算法作为免费、确定性的降级路径。只有开放模型在真实游戏素材上形成稳定失败样本后，才评估定制数据集和微调。

## 证据与边界

### 已确认

- 当前 Agent 自动抠图使用本地 Pillow 色键算法：以四角平均色为背景色，根据 RGB 欧氏距离计算 Alpha。
- 当前实现只改变 Alpha，不执行 despill、前景色重建或边缘收缩，因此抗锯齿边缘可能保留背景颜色。
- `Agent 果冻森林资源演练` 的四张拆分图均出现洋红细边，质量检查已明确返回 `passed=false`。
- 参考视频展示的是“框选/自动定位对象 → 自动处理 → 保存层级、名称和引擎结构”的组合流程，不是单一色键算法。
- 参考视频作者公开说明其抠图模型为自训练模型，未公开基础模型、网络结构和训练数据；视频中的公开操作以手动框选为主，框选后的处理自动完成。

### 技术推断

- 视频效果更接近框选引导的语义分割与 Alpha Matting，而不是基于固定背景色的阈值抠图。
- 自动命名和 UI 类型判断可能需要 OCR、视觉语言模型或定制分类器；视频没有公开具体实现。
- 若要恢复被前景遮挡的完整背景或可独立移动的重叠层，还需要背景修复或生成式补全；单纯抠图不能恢复不可见像素。

### 当前不承诺

- 不承诺未经训练即可达到参考视频私有模型完全相同的边缘质量。
- 不把候选模型名称写成最终依赖；模型许可证、显存、速度和中文游戏 UI 效果需要真实评估。
- 不在第一阶段自动补全被遮挡背景，也不默认调用付费 MCP。

## 能力分级

| 级别 | 路径 | 适用输入 | 主要处理 | 降级关系 |
|---|---|---|---|---|
| M0 | 保留原 Alpha | 已有有效透明通道 | 校验、裁边、拆分 | 无需抠图 |
| M1 | 本地色键 | 背景颜色稳定、主体不用背景色 | 背景估计、阈值与 softness | 当前已实现 |
| M2 | 增强色键 | 纯色或近纯色背景 | M1 + despill + 边缘收缩/扩张 + 柔边修复 | AI 不可用时的推荐路径 |
| M3 | 框选引导 AI Matting | 复杂背景、柔边、玻璃、光效 | 框选/粗分割、trimap、软 Alpha、边缘净化 | 失败时回到人工调整或 M2 |
| M4 | 自动分层 | 完整 UI、场景或多对象设计图 | 自动检测、逐层 Matting、命名、层级和坐标 | 先生成建议，用户确认后执行 |

级别是处理能力，不等同于项目验证等级。每次运行必须记录实际选择的路径、执行器、模型/算法版本和降级原因。

## 核心流程

```text
生成结果 / 外部导入
        |
        v
透明通道与背景特征预检
        |
        +--> 有效 Alpha --------------------------> M0 校验
        |
        +--> 稳定纯色背景 ------------------------> M1/M2 色键
        |
        +--> 复杂背景或高质量边缘要求
                    |
                    v
           手动框选 / 自动候选框
                    |
                    v
           粗分割 -> trimap -> AI Matting
                    |
                    v
       despill / edge contract / 孤立噪点清理
                    |
                    v
     单层透明图 + 坐标尺寸 + 层级 + 来源记录
                    |
                    v
        拆分与命名 -> 质量门禁 -> 入库/返工
```

### 1. 输入预检

- 读取真实宽高、格式、Alpha 范围、四角颜色和边缘颜色分布。
- 请求尺寸与实际尺寸不一致时记录警告，不静默改写真实尺寸。
- 已有有效 Alpha 时默认保留，除非用户明确要求重新抠图。
- 判断背景是否近似稳定纯色，输出置信度而不是只返回布尔值。

### 2. 区域定位

- 第一版以手动矩形框为可靠入口；框只限定感兴趣区域，不直接等同于最终裁剪边界。
- 自动模式可使用对象检测、OCR、视觉语言模型或分割模型生成候选框。
- 自动候选必须可增删、合并、调整和排序；未确认的候选不得直接入库。
- 框、点提示、负点提示和用户修正记录为步骤输入，保证重跑可复现。

### 3. 粗分割与 Alpha Matting

- 粗分割负责确定主体范围，候选技术包括 SAM2 或同类提示式分割模型。
- Matting 负责预测连续 Alpha，候选技术包括 ViTMatte、BiRefNet、BRIA RMBG 或 Matting Anything 类方案。
- SAM 类二值分割不能单独承担玻璃、烟雾、光效和抗锯齿边缘；需通过 trimap 或软 Alpha 模型细化。
- 具体模型需通过相同输入集比较边缘、透明材质、速度、显存、许可证和离线可用性后再确定。

### 4. 边缘后处理

- `despill`：降低透明边缘中与背景色相关的溢色，同时避免破坏主体本身的合法颜色。
- `edge_contract`：可选 0–2 px 边缘收缩，默认不应侵蚀细线、发丝和光效。
- `edge_feather`：在收缩后恢复可控柔边，不能把硬边统一模糊。
- 清理小面积孤立噪点、Alpha 孔洞和边缘锯齿；所有参数写入处理记录。
- 棋盘格、白底、黑底和互补色底板都应进入自动或人工质量检查。

### 5. 拆分、命名与层级

- 每个结果保存透明 PNG、原图坐标、裁剪边界、画布尺寸、层级顺序和源对象 ID。
- OCR 负责可见文字；视觉分类负责按钮、图标、角色、面板、背景和装饰等类型建议。
- 自动名称是建议值，必须支持人工修改；文件名、显示名和语义标签分开保存。
- 对重叠对象，只能抠出可见部分。需要完整独立层时，另建背景修复/对象补全动作并明确标记为生成内容。

### 6. 质量门禁

`quality.review` 必须是控制流门禁，而不是只记录结论：

- `passed=true`：允许入库和保存可复用流程。
- `passed=false`：保留输出和问题证据，阻断自动入库与成功收尾，进入返工、人工确认或失败状态。
- 建议检查项至少包括：主体完整、透明有效、背景残留、溢色、边缘侵蚀、透明材质、对象数量、风格一致性和尺寸契约。
- 自动指标不能替代棋盘格与多底色人工复核；人工结论和证据图同样需要持久化。

## 执行器与能力协商

建议把图片处理能力与图片生成能力分开声明：

```json
{
  "image_processing": {
    "preserve_alpha": true,
    "chroma_key": true,
    "despill": false,
    "box_guided_segmentation": false,
    "alpha_matting": false,
    "automatic_layering": false
  }
}
```

候选执行器：

- `local_classic`：M0–M2 本地确定性算法，无远端费用。
- `local_model`：本地 GPU/CPU 模型，模型缺失时必须在模型管理中显示。
- `server_mcp`：通过 MCP 调用外部处理服务，提交前报告费用与隐私边界。
- `agent_native`：Agent 自身能够处理图片并按输出契约回传 Alpha 图、层级和证据。

配方应保存“需要的能力”和协商策略，不应把创建配方时临时选择的执行器伪装成永久执行器。

## 建议的数据记录

以下字段是后续契约设计建议，当前 API 尚未全部实现：

- `matte_mode`：`preserve_alpha`、`chroma`、`enhanced_chroma`、`box_guided_ai`、`automatic_layering`。
- `executor`、`algorithm`、`model_id`、`model_version`、`device`。
- `source_record_id`、`source_action_id`、`workflow_run_id`、`agent_run_id`。
- `regions`：矩形框、提示点、层级、名称建议、用户修正。
- `alpha_stats`：透明/半透明/不透明像素占比与边缘统计。
- `postprocess`：despill、收缩、扩张、柔边和噪点参数。
- `quality_review`：检查项、证据、结论、操作者和时间。
- `fallback_reason`：模型缺失、显存不足、超时、费用未批准或质量未通过。

## 工具内可见留痕

API 落盘不等于用户可见。所有 Agent 和自动化处理必须在当前项目中提供：

- 运行列表及真实终态；
- 步骤级输入、输出、错误、重试和时间；
- 原图、抠图图、拆分图和质量证据的统一大图预览；
- 算法/模型、参数、费用、降级路径和来源链；
- 从运行跳转到生成历史、处理接收单、资产管理和流程配方的入口；
- 刷新与服务重启后恢复同一记录，不把持久化数据藏在文件系统中。

## 分阶段实施建议

### 阶段 0：修复现有控制流与可见性

- 让 `quality.review.passed=false` 阻断入库和成功收尾。
- 在工具中展示 Agent 运行、步骤、问题和关联产物。
- 保留本次失败演练作为回归数据，不覆盖原记录。

### 阶段 1：增强色键

- 增加可配置 despill、0–2 px edge contract 和多底色检查。
- 用果冻森林原图回归洋红细边，同时验证合法洋红主体不会被错误清除。

### 阶段 2：框选引导 AI Matting

- 先支持单个/多个手动框和本地开放模型。
- 模型不可用时明确降级到增强色键或人工处理，不自动下载未知依赖。
- 处理结果继续写入现有生成历史、processing-intake 和项目文件。

### 阶段 3：自动分层与命名

- 自动产生候选框、OCR 文字、语义类型、名称和层级建议。
- 用户确认后批量处理，并导出引擎可消费的层级清单。

### 阶段 4：定制训练

- 从真实失败样本建立已授权的数据集和 Alpha/trimap 标注。
- 只有开放模型在目标素材上存在稳定、可量化缺口时才启动微调。
- 训练数据来源、许可证、模型版本和评估集必须可追溯。

## 未来实施的最小验证集

后续进入实现时按 L3 完整回归，至少覆盖以下 14 类场景：

1. 已有透明通道直接保留。
2. 纯色背景基础色键。
3. 近纯色背景增强色键。
4. despill 清除背景溢色。
5. 合法背景同色主体不被误删。
6. 手动单框 AI Matting。
7. 多框逐对象输出。
8. 发丝、柔边和抗锯齿。
9. 玻璃、烟雾或光效的半透明 Alpha。
10. 自动候选框的增删、调整和排序。
11. OCR、类型和名称建议可修改并持久化。
12. 模型缺失、显存不足和超时的明确降级。
13. `passed=false` 阻断入库与流程成功收尾。
14. 刷新、服务重启和幂等重跑保持来源链一致。

## 待讨论

- 第一批目标素材优先级：独立道具、角色、游戏 UI、特效还是完整场景。
- 本地模型优先还是 MCP 优先，以及允许的模型大小、显存和单图处理时间。
- 是否需要背景修复和遮挡对象补全，还是第一阶段只处理可见像素。
- 自动分层的人工确认点、费用策略和默认最大层数。
- Unity、Cocos、Godot 和通用 PSD/JSON 导出的首个目标格式。
