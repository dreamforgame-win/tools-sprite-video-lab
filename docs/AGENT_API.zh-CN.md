# Agent 编排 API

灵帧工坊通过持久化 Agent 运行提供机器可执行的素材生产流程。Agent 不需要操作网页；它读取协议清单、声明能力、创建运行、执行 `next_actions`，并把结构化结果或原生生成图片回传。

## 设计边界

- API 负责状态机、项目文件、来源追溯、MCP 生成、处理、入库、幂等和恢复。
- Agent 负责理解自然语言需求、编译具体步骤，以及执行标记为 `agent` 或 `agent_native` 的动作。
- 服务端不会根据模型名称猜测 Agent 是否能够生图。Agent 必须在创建运行时声明 `native_image_generation`。
- Agent 原生生图和服务端 MCP 生图都写入同一份项目生成历史，后续抠图、拆图和入库不区分来源。
- `workflowRecipe` 是可复用、版本化的步骤模板；`agentRun` 是一次不可替代的实际执行记录，并关联基础 `workflowRun` 审计记录。

## 协议入口

```http
GET /api/v1/agent/manifest
```

清单返回协议版本、动作类型、执行器、能力字段、引用语法、结果契约和安全要求。Agent 应先读取清单，再创建运行。

## 主要接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/v1/agent/manifest` | 读取 Agent 协议 |
| GET/POST | `/api/v1/projects/{projectId}/workflow-recipes` | 列出或创建流程配方 |
| GET/PATCH | `/api/v1/projects/{projectId}/workflow-recipes/{recipeId}` | 读取配方版本或创建新版本 |
| GET/POST | `/api/v1/projects/{projectId}/agent-runs` | 列出或创建 Agent 运行 |
| GET | `/api/v1/projects/{projectId}/agent-runs/{runId}` | 刷新运行并取得下一步 |
| POST | `/api/v1/projects/{projectId}/agent-runs/{runId}/actions/{actionId}/result` | 回传结构化 Agent 结果 |
| POST | `/api/v1/projects/{projectId}/agent-runs/{runId}/actions/{actionId}/artifacts` | 回传 Agent 原生图片 |
| POST | `/api/v1/projects/{projectId}/agent-runs/{runId}/actions/{actionId}/retry` | 重试失败动作 |
| POST | `/api/v1/projects/{projectId}/agent-runs/{runId}/approve` | 批准付费动作 |
| POST | `/api/v1/projects/{projectId}/agent-runs/{runId}/cancel` | 取消未提交动作 |
| POST | `/api/v1/projects/{projectId}/agent-runs/{runId}/resume` | 恢复非终态运行 |

所有创建、结果回传和付费提交请求都应发送 HTTP `Idempotency-Key`。

## 创建运行

```json
{
  "request": "制作一套像素风角色素材，完成抠图、拆分并入库",
  "capabilities": {
    "native_image_generation": true,
    "image_input": true
  },
  "execution_policy": {
    "image_generator": "auto",
    "paid_generation": {
      "mode": "auto_under_budget",
      "max_total": 10,
      "currency": "CNY"
    }
  },
  "actor": "codex"
}
```

没有提供 `recipe_id` 或 `steps` 时，运行首先返回 `workflow.plan`。Agent 需要把原始需求编译成具体步骤并提交：

```json
{
  "result": {
    "steps": [
      {
        "id": "define-style",
        "type": "style.define",
        "instructions": {
          "goal": "提炼颜色、形状、材质、比例和负面约束"
        }
      },
      {
        "id": "create-style",
        "type": "style.create",
        "depends_on": ["define-style"],
        "inputs": {
          "name": "Soft Pixel",
          "description": {
            "$from": "define-style",
            "path": "description"
          }
        }
      }
    ]
  }
}
```

输入引用只使用以下结构，不使用任意表达式：

```json
{"$from": "create-style", "path": "style_id"}
```

被引用动作必须已成功，`path` 使用点号访问对象字段或数组索引。

## 两种图片执行方式

### Agent 原生生图

当 `native_image_generation=true` 且策略为 `auto` 或 `agent_native` 时，`image.generate` 返回：

```json
{
  "id": "generate-hero",
  "type": "image.generate",
  "executor": "agent_native",
  "status": "action_required",
  "resolved_inputs": {
    "prompt": "single pixel-art hero...",
    "model": "agent-native",
    "asset_node_id": "asset_xxx",
    "params": {"resolution": "1K"}
  },
  "artifact_url": "/api/v1/projects/default/agent-runs/arun_xxx/actions/generate-hero/artifacts"
}
```

Agent 根据 `resolved_inputs` 和 `output_contract` 生成图片，然后回传：

```json
{
  "data_url": "data:image/png;base64,...",
  "file_name": "hero.png",
  "metadata": {
    "native_model": "gpt-image",
    "notes": "generated by the calling Agent"
  }
}
```

只接受 PNG、JPEG、WebP，单图最大 20 MB。服务端验证图片内容、尺寸和哈希后写入项目 `production/images/`，并创建标准生成记录。API 不接受客户端绝对路径。

### 服务端 MCP 生图

当 Agent 不声明原生生图能力，或策略指定 `server_mcp` 时，服务端根据模型能力和参数报价：

- `manual`：进入 `awaiting_approval`，调用批准接口后提交。
- `auto_under_budget`：报价币种匹配且总价不超过预算时自动提交。
- `always`：直接提交；调用方应在创建运行前已取得用户授权。

MCP 任务使用生成记录 ID 恢复和轮询。服务重启或 Agent 重新连接后，只需再次读取运行，不得重复创建任务。

## 标准动作

| 动作 | 执行器 | 输出 |
|---|---|---|
| `workflow.plan` | Agent | 具体步骤数组 |
| `style.define` | Agent | 风格契约 |
| `style.create` | 服务端 | 风格方向 ID |
| `style.confirm` | 服务端 | 当前确认风格 |
| `asset.plan` | Agent | 资产清单与生成规格 |
| `asset.create` | 服务端 | 具体资产节点 ID |
| `image.generate` | 协商 | 标准生成记录 |
| `image.matte` | 服务端 | 抠图结果记录与处理接收单 |
| `image.split` | 服务端 | 分区、拆分图片记录与处理接收单 |
| `quality.review` | Agent | 通过状态或问题清单 |
| `library.ingest` | 服务端 | 入库资产 ID |
| `flow.save` | 服务端 | 新流程配方 ID 和版本 |

自动抠图第一版支持 `auto`、`chroma`、`edge_connected_chroma` 和 `none`。自动拆分优先使用透明通道，并按横纵空隙产生单主体分区；处理结果仍带源生成记录、工作流、动作和文件哈希。

## CLI

```powershell
python sprite_lab_cli.py agent-manifest
python sprite_lab_cli.py create-agent-run default --request "制作角色素材"
python sprite_lab_cli.py get-agent-run default arun_xxx
python sprite_lab_cli.py submit-agent-result default arun_xxx plan --result '{"steps":[...]}'
python sprite_lab_cli.py submit-agent-artifact default arun_xxx generate-hero --file F:\temp\hero.png
python sprite_lab_cli.py approve-agent-run default arun_xxx --action-id generate-hero
python sprite_lab_cli.py cancel-agent-run default arun_xxx
```

CLI 读取显式指定的本地图片并转换为受控回传内容；REST API 本身仍不接受任意文件路径。

## 恢复与错误

- `next_actions` 是当前可执行或需要关注的动作，不代表完整历史；完整步骤保存在 `steps`。
- 失败动作通过 `/retry` 复位，重试次数写入运行和基础 `workflowRun`。
- 取消会阻止尚未提交的动作。已经提交给外部 MCP 的任务可能继续完成并产生费用。
- 已取消运行不可恢复；失败运行需要先重试失败动作。
- 所有错误响应使用 `{"ok": false, "error": "..."}`，不得包含 Token。
